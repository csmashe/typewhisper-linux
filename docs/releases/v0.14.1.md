# TypeWhisper Linux v0.14.1

TypeWhisper Linux 0.14.1 primarily brings **upstream dictation, personalization,
and provider improvements to Linux**. Most of the feature work in this release
was ported and adapted from upstream, with additional Linux integration fixes,
testing, and CI cleanup.

Highlights include **ordered language hints**, **spoken-formatting strategies**,
and **optional paste locking to the initial text field**, alongside richer
dictionary rules, profile matching, provider settings, and a configurable
filler-word plugin.

Two upgrade details matter: **Dashboard usage counts now survive history
cleanup**, including when history saving is disabled, and the updated OpenAI
plugin requires **host 0.14.1 or later** because it uses a new SDK type.

## New Features

- **Ordered language hints.** Add additional languages after the main spoken
  language in Dictation settings, and override the list in a profile. Engines
  that support multiple hints receive the ordered list; other engines use the
  primary language, with prompt hints where supported. Existing single-language
  settings migrate automatically. The local API also accepts ordered hints.
- **Spoken formatting strategies.** Choose Automatic, Native only, or Fallback
  only for microphone dictation. Local rules cover English, German, Spanish,
  and Russian punctuation and layout commands. A verification panel lets you
  save overrides for an engine, model, and language, including whether its
  native formatting works. Automatic is the default. This new strategy does
  not add command interpretation to file transcription or HTTP uploads.
- **Regional spelling.** Choose US or UK English output, or Swiss German
  `ß` → `ss` conversion. As transcribed remains the default; the Germany and
  Austria choices currently preserve German spelling. Literal tokens and
  dictionary replacements are protected from regional rewriting.
- **Short-utterance punctuation.** The new **Keep punctuation in short
  utterances** setting is on by default. Turn it off to remove model-added
  greeting commas and sentence-ending punctuation from one- or two-word
  utterances.
- **Lock paste to the initial text field.** This opt-in setting restores the
  field focused when dictation started before pasting. If that field cannot
  be restored safely, the result stays on the clipboard. It requires the
  accessibility listener enabled by **Learn corrections from other apps**;
  enabling that prerequisite also enables correction learning.

- **Dictionary patterns and escapes.** Corrections support regular expressions and replacement escapes
  such as `\n` for a line break and `\t` for a tab. Existing literal entries
  retain their behavior. Replacement text remains literal with respect to regex
  capture tokens: `$1` and `$&` are not expanded. Invalid or slow patterns do
  not stop the remaining corrections.
- **Profile matching modes.** Profiles can match **App and website** or **App or website**. Existing
  profiles preserve the requirement to match both when both rule types are
  present; the editor also offers the more permissive alternative.
- **Filler Words plugin.** The bundled post-processing plugin removes configurable
  filler words locally, with language-specific lists. Enable it from Plugins
  and edit its list independently of the transcription provider.
- **Plugin activation tabs.** Plugins are separated into **Enabled** and **Disabled** tabs with counts
  and empty states. Changing activation preserves settings and expansion state.

- **Persistent Dashboard statistics.** Usage totals, streaks, activity days,
  language/model breakdowns, and hour-of-day counts now come from a separate
  aggregate store. Available history is imported once, and calendar summaries
  refresh at local midnight. History-derived recent activity and reliability
  details remain separate; see the retention note below.
- **About links and install location.** About adds project/support links and
  an action to open the running application's install location.

- **ElevenLabs:** choose Automatic streaming with REST fallback or REST only;
  configure filler/stumble cleanup, REST audio-event tags, and REST speaker
  count. Zero speakers means automatic detection; explicit counts are 1–32.
- **Soniox:** select United States, European Union, Japan, or India data regions.
  Testing an API key can switch to the region accepted by its project. Ordered
  language hints are supported on both batch and streaming paths.
- **OpenAI:** discover available language and audio models dynamically, keep
  cached selections when catalog requests fail, apply language parameters
  according to the selected model, and respect dictionary-term budgets.
  ChatGPT login remains for prompt processing; transcription and TTS require
  an API key.
- **OpenAI-Compatible:** configure the LLM request timeout per endpoint.
- **Gemini:** discover compatible Gemini and Gemma chat models, retain built-in
  aliases as a fallback, and send reasoning controls only for supported models.
  Gemini transcription is not part of this release.

## Fixes

- **Catalog failures preserve OpenAI selections.** A failed refresh keeps the
  saved/default models instead of replacing a user's selection with an empty
  or incomplete catalog. Selections stay associated with their authentication
  mode.
- **Plugin settings survive activation changes.** Moving a plugin between
  Enabled and Disabled keeps its settings and expansion state intact.

## Plugin SDK

- `ITranscriptionEngineRole` gains `SupportsLanguageHints` and
  `TranscribeWithLanguageHintsAsync`, `StartStreamingWithLanguageHintsAsync`,
  and `TranscribeStreamingWithLanguageHintsAsync`. Default implementations
  preserve the existing single-language path.
- `DictionaryTermsBudget` and `PluginDictionaryTerms` let providers advertise
  term limits and normalize, clip, and format dictionary prompts consistently.
- The updated OpenAI plugin declares **minimum host 0.14.1**, because it uses
  the new dictionary-budget SDK type. Upgrade the host before installing that
  plugin independently.

## Under the Hood

- **Usage storage.** Daily aggregates are written to `usage-statistics.json`
  under the application data directory. Existing available history is imported
  once; already-deleted history cannot be reconstructed.
- **Local API.** Multipart `language_hint` values and JSON `languageHints`
  arrays retain their order. Profile responses expose `inputLanguageHints`.
- **CI and test cleanup.** CodeQL actions use v4, test resource-disposal
  warnings are cleaned up, and the dashboard midnight-scheduling test waits
  for history initialization to avoid concurrent test refreshes.

## Notes

- **History cleanup does not reset usage counts.** Deleting history, shortening
  retention, or disabling history saving does not erase or stop the aggregate
  statistics. The store contains counts and breakdowns rather than transcript
  text. Recent activity, insertion reliability, and writing-assist details still
  depend on retained history and may cover less data than the headline totals.
- **Focused-field paste requires correction learning's listener.** Turning on
  **Learn corrections from other apps** to make paste locking available also
  enables correction learning; it is not a separate listener-only permission.
- **Existing defaults are preserved where possible.** Regional spelling starts
  at As transcribed, short-utterance punctuation stays on, and focused-field
  paste stays off. Spoken formatting defaults to Automatic. Existing profiles
  with both app and website rules retain their requirement to match both.
- All new interface strings are translated across **English, German, Spanish,
  and Russian**.
- **Included scope.** PRs #42, #75, #76, #77, #79, #78, #80, #81, #82, #83, #85,
  and #86. Dictation recovery, Gemini transcription, Microsoft and Meta
  providers, Authenticated CLIs, and screen/clipboard reference context remain
  deferred.
