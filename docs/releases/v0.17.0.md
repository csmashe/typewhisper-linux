# TypeWhisper Linux v0.17.0

TypeWhisper Linux 0.17.0 makes local models more reliable. It adds
**Parakeet Ultra 0.6B**, a more accurate Parakeet model, **makes Supertonic
speech work** (it never worked in the Linux app), **fixes the prompt format
the Gemma 4 (Local) plugin sent**, keeps **words and token timings in long
Sherpa recordings**, and lets **idle Gemma models be released** from memory
without losing their place in prompts and translation. Local model downloads
now **check free disk space first, resume after an interruption and verify
every file** before it is used. Dictionary terms reach the **Meta**
transcription plugin whole, during dictation as well as through the API.
Most of it was ported and adapted from upstream (`c2fcea53` and later
fixes); where the Linux port deliberately differs, the notes say so.

Nothing needs to be downloaded again after upgrading: model files already on
disk are checked once and kept. Two plugins, Supertonic and Meta, now require
this version of the app.

## New Features

- **Parakeet Ultra 0.6B.** A new Sherpa-ONNX model (~670 MB, int8), listed
  first and marked recommended. It is Moondream's post-trained
  `parakeet-tdt-0.6b-v3`, with the same 25 languages as Parakeet TDT and lower
  reported word error rates (for example 11.62 → 9.55 % on FLEURS). It gets
  everything Parakeet TDT does: long-recording token timings, acoustic
  dictionary boosting and the German spoken-formatting hint. Your selected
  model does not change; choose Ultra in **Transcription Engines** to use it.
  The files are upstream TypeWhisper's int8 export, mirrored unchanged to this
  repository's `model-parakeet-ultra-int8-v1` prerelease.
- **Idle Gemma models are released.** **Advanced → Auto-unload idle models**
  (previously "Auto-unload model") now applies to the Gemma 4 (Local) text
  model as well as the speech model. A released model stays selected and
  ready: prompts, translation and memory still offer it, and the next request
  loads it again (about 2 s for E2B on a warm disk cache). A release waits for
  a running request, load or download. A changed setting applies within a
  minute, also to a model that is already idle. The default is still
  **Never**. Gemma's settings show "Model ready. It is not in memory now and
  loads on its next use." while it is released.
- **Supertonic model controls.** The Supertonic settings now have **Download
  model files** and **Remove model files** buttons, with a progress bar and
  Cancel. Removal asks first, waits for speech in progress and deletes only
  the model's own files. **Validate** now only reports whether the model is
  ready. Any plugin can offer such buttons through the new settings-actions
  SDK interface below.
- **Free-space check before downloads.** Whisper, Gemma, Sherpa, CTC
  dictionary and Supertonic models, the Sherpa and whisper.cpp GPU runtimes
  and the CUDA wheels check the disk that will hold them before downloading,
  including room to extract archives and a 256 MB reserve. A full disk is
  reported as "Not enough disk space for …" with the required and available
  amounts, instead of a bare `No space left on device` part-way through.
  Nothing is deleted to make room, and a partial download is kept so a retry
  after freeing space continues where it stopped.
- **Resumable, verified model downloads.** Gemma, Sherpa (Parakeet, Canary)
  and Supertonic model files are pinned to a fixed revision with an exact
  size and SHA-256. A dropped connection resumes from where it stopped, and a
  file is used only after it matches. A corrupt or truncated file is removed
  and fetched again. A check is remembered beside the file, so later sessions
  do not hash multi-gigabyte models again.
- **Whole dictionary terms for Meta.** Engines can now ask for dictionary
  terms as a list instead of one comma-joined string, so a term like
  `Washington, D.C.` stays one term. Meta is the first engine to use it, and
  now receives your dictionary terms during dictation, live preview,
  streaming, retry from History and file transcription, not only through the
  HTTP API. A term that does not fit Meta's keyword limits is dropped whole
  rather than cut. Other engines are unchanged.

## Fixes

- **Supertonic speech never worked.** Every synthesis failed with
  `DllNotFoundException`, because nothing in the plugin mapped ONNX
  Runtime's `onnxruntime.dll` import to the bundled `libonnxruntime.so`. The
  plugin now loads its own copy. Text is also framed as `<lang>text</lang>`
  like Supertone's reference code, generated speech is capped at two minutes,
  and a model that fails to load part-way releases what it had loaded.
- **Gemma 4 received no turn structure.** The plugin sent Gemma 3's
  `<start_of_turn>` prompt format, which is not in the Gemma 4 vocabulary. It
  now uses the Gemma 4 template with thinking off, stops at the end of the
  turn and hides any reasoning block. Text you type that looks like a control
  marker (such as `<|channel>`) stays literal. Long prompts can be cancelled,
  the context grows from 4,096 to 8,192 tokens, and one context is reused
  between requests.
- **Gemma requests before its model finished loading** failed with "No model
  loaded". The request now loads the model itself.
- **Long Sherpa recordings lost words and timings.** Recordings over 15 s
  were joined by deleting the longest word run the chunks shared, which
  removed a genuinely repeated word ("that that"), and they published no
  token timings, so acoustic dictionary boosting silently stopped. Chunks
  now cut at the quietest point and are evenly sized. Canary joins
  non-overlapping chunks directly; Parakeet pairs the words both chunks
  heard at each cut. On 292 real recordings over 15 s this reduced missing
  words from 406 to 361 and extra words from 243 to 177, and 247 of 248
  multi-chunk recordings now carry token timings.
- **Parakeet token durations were garbage.** The sherpa-onnx C# binding reads
  its `Durations` field from the wrong offset of the native result (also on
  sherpa-onnx `master`), so acoustic boosting checked windows that were far
  too short or too long. TypeWhisper now reads the durations from the native
  result and uses them only when they match the decoded tokens.
- **The acoustic boosting status named only Parakeet TDT.** The Dictionary
  page said "Active with Parakeet TDT 0.6B" even with Parakeet Ultra selected,
  and asked for "the local Parakeet TDT engine" when inactive. It now says
  "Active with the local Parakeet model." and "requires a local Parakeet
  model, Ultra or TDT".

## Plugin SDK

All additions are optional, and plugins built against the previous SDK keep
loading.

- `IPluginSettingsActions`: `GetSettingsActions()` and
  `ExecuteSettingsActionAsync(id, ct)`, with `PluginSettingsAction` (label,
  description, enabled state, optional confirmation). The Plugins page shows
  them as buttons and runs one action per plugin, without the validation
  time limit. The host now also shows `IPluginSettingsActivity` progress with
  a Cancel button.
- `IPluginHostServices.LocalModelIdleTimeout` (`TimeSpan?`, default `null`):
  how long a local model may stay idle before the plugin releases it. The
  host maps it from **Auto-unload idle models**. A plugin built against this
  SDK that runs on an older host should read it from a separate non-inlined
  method and treat `MissingMethodException` as `null`, as Gemma does.
- `ITranscriptionEngineRole.SupportsStructuredDictionaryTerms` (default
  `false`) and `PluginTranscriptionPrompt`: an opted-in engine receives a
  versioned envelope in the existing `prompt` argument that keeps the
  caller's prompt text apart from the dictionary terms. `Parse(prompt)`
  accepts plain text too; a malformed envelope throws `FormatException`. The
  engine's `DictionaryTermsBudget` is applied to the terms before encoding.
- The bundled Supertonic and Meta plugins now declare `minHostVersion`
  0.17.0, because they use the new interfaces. Gemma uses the idle timeout
  but keeps its floor, because it falls back as described above.
- Bundled plugin versions: Gemma 4 (Local), Sherpa-ONNX, Supertonic and Meta
  1.1.0; whisper.cpp 1.0.1; Parakeet CTC Vocabulary 0.1.1.

## Under the Hood

- LLamaSharp and its CPU backend are updated from 0.26.0 to 0.27.0.
- Downloads share one free-space policy (`plugins/Shared/Net/DownloadSpace.cs`),
  measured against the filesystem that will hold the file, following
  symlinks. `ResilientDownloader` checks the server's declared remainder plus
  any extraction space before writing. Two downloads that start at the same
  time can both pass the check; the second then reports running out of space.
- The cross-process download lock now retries only when the lock is held
  elsewhere; any other I/O error, such as a full disk, is reported instead of
  retried forever.
- Gemma accepts earlier cached builds of the same weights that differ only in
  embedded template metadata. Earlier re-quantizations of the 26B model are
  not accepted and download again.
- Compared with upstream, Gemma releases its own model when idle because the
  Linux host has no plugin runtime registry or worker processes, and Sherpa
  keeps 15 s chunks instead of upstream's 300 s Parakeet calls so cancellation
  stays bounded.
- `THIRD-PARTY-NOTICES.md` in the Sherpa plugin gives the CC BY 4.0
  attribution for Parakeet Ultra, Parakeet TDT and Canary.
- Pull-request CI now runs only while a PR carries the `ci` label.
- Test suites at release: Core 1141, Linux 3044, Integration 78,
  PluginSystem 2884, Cli 197.

## Notes

- **No re-downloads.** Gemma, Sherpa and Supertonic files already on disk are
  hashed once on first use after the upgrade (about 2 s for a 3 GB Gemma
  model) and kept. Only a file that fails the check is fetched again.
- **Parakeet Ultra** is not selected automatically. Pick it in
  **Transcription Engines** if you want it; Parakeet TDT and Canary keep their
  IDs, so saved selections and profiles are unchanged.
- **Releasing idle Gemma models** is off unless **Auto-unload idle models**
  is set to a duration. A release that lands while you are dictating means
  that dictation's prompt step loads the model first.
- **Supertonic** downloads through its **Download model files** button now;
  **Validate** no longer downloads.
- **Meta** users now send their enabled dictionary terms with every
  transcription. Disable a term in the Dictionary to keep it out.
