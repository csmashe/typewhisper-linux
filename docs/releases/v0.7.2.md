# TypeWhisper Linux v0.7.2

TypeWhisper Linux 0.7.2 is an onboarding and first-run setup release. It makes
the welcome wizard machine-aware: instead of a passive checklist, it detects
your desktop and session and drives each piece — clipboard, automatic paste, the
global dictation shortcut, and active-window detection — to a working state, so
finishing setup means dictation actually works. The dictation shortcut now uses
the app's own input backend so a held key does proper push-to-talk, and several
first-run papercuts are fixed.

## New

- **Machine-driven setup checklist.** The wizard's setup step now lists the
  things this specific machine needs and fixes them in place — each item knows
  whether it applies to your desktop/session, shows its current state, and offers
  a one-click action. Required items gate "Finish" so completing the wizard means
  you're genuinely ready (Skip is still available). The framework is desktop- and
  session-agnostic, so the same wizard configures GNOME, KDE, and wlroots
  compositors without hard-coding any one of them.
- **One-click package installs.** Missing helpers (ydotool, wl-clipboard,
  ffmpeg, …) can be installed straight from the wizard through a single admin
  prompt, with the exact distro command shown as a copyable fallback. The
  package manager is detected from your distribution (dnf / apt / pacman /
  zypper).
- **Push-to-talk that actually holds.** The global dictation shortcut is now
  driven by the app's own input backend rather than a desktop "custom shortcut."
  Desktop shortcuts only deliver a single press pulse (no key-release), so they
  can't do hold-to-talk and thrash on a held key. On Wayland the wizard offers to
  add you to the `input` group (one admin prompt, then a single log-out/in) so
  the app can read key press *and* release for real hold-to-talk. The default
  recording mode is now **Hybrid**: a quick tap toggles, a held key records only
  while held.

## Improvements

- A fresh install now enables only the offline, no-API-key transcription engines
  (whisper.cpp, sherpa-onnx) by default, so the model list works out of the box
  instead of being cluttered with cloud providers you'd have to key in first. Add
  cloud providers any time from the Plugins tab.
- The ydotool one-click setup restarts the `ydotoold` daemon after installing its
  udev rule, so it can't keep a stale `/dev/uinput` handle and silently fail to
  type while looking configured.
- Active-window detection now recognizes both the "Window Calls" GNOME extension
  and the "Window Calls Extended" fork, and verifies the extension actually
  responds rather than assuming it's present.

## Fixes

- Fixed a false positive where active-window detection reported the "Window
  Calls" extension as installed when it wasn't — it now calls the extension's
  method instead of merely introspecting a D-Bus path that always answers.
- Fixed unreadable dark-on-dark text (model size and "Recommended" labels) in the
  onboarding model dropdown, and forced the app to its intended dark theme so
  controls render correctly regardless of the system light/dark setting.
- The onboarding model dropdown now shows a live download progress bar instead of
  appearing to stall, and the heavy per-model refresh no longer runs on every
  progress tick.

## Not Ported From Windows

- Windows release channels and Velopack update-channel controls are not part of
  this Linux branch; the Linux app checks GitHub Releases for updates but installs
  them manually.
- Windows-specific workflow automation and packaging changes remain Windows-only.
