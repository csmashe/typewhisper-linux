# TypeWhisper Linux v0.16.0

TypeWhisper Linux 0.16.0 adds **acoustic dictionary boosting** — a second,
small speech model that checks misheard dictionary terms against the audio
instead of only against their spelling — together with **recorder
pause/resume and in-app playback**, a **read-last-transcription shortcut**
and **Read aloud in History**, **multi-select delete and export in History**,
**detected-language reporting for streaming engines**, and a set of fixes,
one of which unblocks file transcription and the HTTP API for the Sherpa
engine. All of it was ported and adapted from the upstream 2026-09-14
baseline (`c10b713c`); where the Linux port deliberately differs, the notes
say so.

Two things matter when upgrading: the new **Parakeet CTC Vocabulary** plugin
is **off by default** and downloads its ~126 MB model once when you enable
it, and the Dictionary CSV format gains an eleventh column
(`CtcMinSimilarity`) that older builds ignore on import.

## New Features

- **Acoustic dictionary boosting.** Text-only vocabulary boosting can only
  fix a word that is *spelled* like a term. After a local Parakeet TDT
  transcription, the new stage scores every word that could be a misheard
  term against the recording with the NVIDIA Parakeet TDT-CTC 110M model and
  replaces it only when the audio supports the term — "custral" becomes
  Kestrel, "Fodora" becomes Fedora, "Codec" becomes Codex — without touching
  the neighbouring words. On the maintainer's 20-clip test set it raised term
  recall from 65 % (text boosting) to 81 % while lowering overall word errors.
  It runs on the CPU in roughly 100–400 ms per dictation, for dictation, file
  transcription and the HTTP API alike, and needs three things: the
  **Parakeet CTC Vocabulary** plugin enabled on the Plugins page, the local
  **Parakeet TDT 0.6B** engine (the only one that reports the word timings the
  check needs), and at least one active term in the Dictionary. While the
  stage is active, text-only boosting steps aside for that transcription;
  dictionary corrections still run afterwards. The model is English-only.
- **Dictionary controls for the acoustic stage.** The Dictionary page gains an
  **Enable acoustic dictionary boosting** switch with a status line that says
  why the stage is or is not active (plugin not enabled, engine not Parakeet,
  no active terms, disabled, active), and every term gets a **Boost** button
  cycling **Auto** (engine default, 60 %), **Strong** (50 %, accepts more
  pronunciations), **Balanced** (65 %) and **Precise** (80 %, for a common
  word that keeps turning into the term). The per-term value is stored as
  `CtcMinSimilarity` (0.4–0.95), travels with CSV export/import and backups,
  and is ignored by every other engine.
- **Recorder pause and resume, and playback in the app.** The Recorder can be
  paused and resumed; paused time is excluded from the timer and from the
  60-minute active-audio limit, dictation cannot open the microphone while a
  recording is paused, and stop joins the segments into one WAV. Saved
  recordings play back inside the app; playback stops when a capture starts,
  before a recording is deleted and on shutdown.
- **Recorder routes on the HTTP API.** `POST /v1/recorder/start`,
  `POST /v1/recorder/stop`, `GET /v1/recorder/status` and
  `GET /v1/recorder/session`, token-protected and listed in `/docs` and
  `/v1/capabilities`. Stop waits for the save and returns the file path.
  Sessions started from the API are saved without automatic transcription.
- **Read the last transcription aloud.** A new global shortcut (unassigned by
  default) reads the latest transcription through the speech feedback
  service as a toggle: a second press stops, presses never queue, nothing is
  written to History or the clipboard. It is registered on the SharpHook,
  evdev and portal backends and takes part in the shortcut collision checks.
- **Read aloud in History.** Each History entry gains a Read aloud / Stop
  reading action. Collapsing, editing, deleting or clearing the entry stops
  only that entry's speech and never a newer readback started elsewhere.
- **Multi-select in History.** A selection mode with a checkbox per entry,
  select-all-shown, export of the selection and a confirmed bulk delete. The
  selection is id-based and survives refreshes and filter changes; the
  delete removes exactly the entries that were listed when the confirmation
  opened, keeps audio files still referenced by a remaining record, and stops
  a selected entry that is being read aloud first.
- **Detected language from streaming engines.** Deepgram, ElevenLabs and
  Soniox now report the language of each streamed segment; the dictation
  result carries it when every final segment agreed, so History and the
  readback language follow the detected language instead of the configured
  one. ElevenLabs' three-letter codes (`deu`, `eng`, …) are folded to the
  two-letter codes the rest of the app uses.

## Fixes

- **Sherpa engine: file transcription and the HTTP API/CLI failed for every
  input.** `ffmpeg` writes streaming WAV headers (data size `-1`) when it
  transcodes to a pipe, and the Sherpa decoder's chunk-size guard rejected
  them with "Invalid WAV data: chunk size out of range" — since v0.10.0.
  Dictation was unaffected. The decoder now treats an out-of-range data size
  as "to end of stream".
- **A saved language no longer blocks auto-detect-only models.** Parakeet TDT
  and Cloudflare ASR detect the language themselves; with a language still
  saved from another engine, every dictation, file transcription and API call
  failed with "does not support explicit language selection" until the user
  found the Auto option. The saved language now degrades to automatic
  detection on such models (and is kept out of the language hints
  downstream), the Dictation page says so, and the API no longer answers 400
  for that case. A model with no detection at all still reports the error.
- **Backup timestamps.** Backups stored entry times as UTC in a field that
  only holds local wall-clock time, so every backup and every restore shifted
  file times by the machine's UTC offset outside UTC.
- **Recorder lifecycle.** Disposing the recorder while a capture was running
  left the microphone stream open; a failed recorder start always releases
  its capture reservation now.
- **History bulk-delete notice** counts the records that still existed, not
  the ids requested.

## Plugin SDK

- `IVocabularyRescorerPlugin` with `VocabularyTermHint`,
  `VocabularyRescoreRequest`, `VocabularyReplacement` and
  `VocabularyRescoreResult`: an optional acoustic refinement stage the host
  calls after transcription. The host validates identity, spans and terms and
  applies the replacements itself.
- `PluginTranscriptionResult.TokenTimings` (init-only, default empty) and
  `VocabularyTokenTiming`, plus `Helpers/TranscriptionTokenTimings.Create`
  for building valid intervals from a decoder's token, timestamp and duration
  arrays. The bundled Sherpa plugin fills them for single-chunk Parakeet
  decodes on CPU and CUDA.
- `StreamingTranscriptEvent.DetectedLanguage` (optional, init-only).
- All additions are new interfaces, records or init-only properties: plugins
  built against the previous SDK keep loading. The bundled Sherpa and
  Parakeet CTC plugins now declare `minHostVersion` 0.16.0.

## Under the Hood

- The Parakeet CTC Vocabulary plugin is a regular bundled plugin (37 bundled
  plugins now) rather than a nested dependency of the Sherpa plugin, which
  the Linux plugin model does not have. It declares mixed network access, so
  it stays opt-in; its model and tokenizer are downloaded from GitHub and
  Hugging Face with pinned checksums through the shared resilient downloader,
  extracted with bounded tar.bz2 handling, and loaded lazily on the first
  rescore, then unloaded after ten idle minutes — the plugin costs no memory
  while another engine is in use. Its own ONNX Runtime (1.24.1) coexists with
  the older runtime inside sherpa-onnx; a test proves both load in one
  process.
- Compared with upstream, the rescorer selects among overlapping candidate
  spans by text similarity first and skips a window that already contains
  the term; upstream's acoustic-margin ranking made the longest span win and
  swallowed neighbouring words ("Open type whisper" → "TypeWhisper"). The
  default similarity threshold is a flat 0.60 instead of an adaptive
  0.52/0.55 that accepted sound-alikes on small dictionaries. Hyphenated
  terms are scored in spoken form (the model's vocabulary has no hyphen) and
  inserted with their exact spelling. Four upstream bugs were fixed on the
  way: a `Dispose` deadlock on a UI thread, frame times computed from the
  window length instead of the fixed 80 ms stride, a float/double threshold
  comparison that rejected exactly 0.6, and a cancelled rescore that could
  publish a late result.
- The host stage has a 10-second timeout (upstream has none), discards a
  result when the plugin changed or became unready during the call, runs the
  plugin on the thread pool, and gates on the engine that produced the
  transcript, captured under the transcription lease. A stage that was busy,
  timed out or failed hands the transcript back to the text-only booster
  instead of leaving it unboosted.
- The language-selection path resolves the effective selection once, in
  `TranscriptionLanguageSelectionInvoker`, for dictation, streaming start and
  preview, recovery retry, file transcription, the HTTP API, transform
  commands and the recorder.
- Recorder capture moved into `RecorderService` with Ready / Recording /
  Paused / Saving states and a capture reservation on the audio service.
- Test suites at release: Core 1002, Linux 2995, Integration 62, PluginSystem
  2599.

## Notes

- **Enabling the Parakeet CTC Vocabulary plugin downloads ~126 MB** once into
  the plugin's data folder (verified by checksum). Nothing is sent anywhere
  at run time.
- The acoustic stage only works with the local Parakeet TDT 0.6B engine; with
  any other engine the Dictionary status line says so and text-only boosting
  behaves as before.
- Sound-alike traps are inherent to acoustic matching: a term such as
  "Codex" can be inserted for a spoken "codec" when the audio genuinely
  matches. The per-term **Precise** preset, or disabling the term, is the
  remedy.
- Dictionary CSV exports now have eleven columns. Older builds import them
  (the extra column is ignored); re-importing a term into a dictionary that
  already has it keeps the existing threshold.
- Upgrading from the local 0.15.3 beta packages: install 0.16.0 over them;
  the plugin's downloaded model is reused.
