# TypeWhisper Linux v0.19.3

TypeWhisper Linux 0.19.3 is a fix release. The **global hotkey comes back
after unlocking hyprlock**, a **microphone unplugged mid-recording no longer
freezes the app**, and switching the **interface language now updates the
whole interface**: generated names, status messages, plugin settings,
Dictionary badges and the browser URL setup results. On Hyprland, **wtype no
longer types garbage into XWayland apps**. Direct typing on ydotool-only
Wayland **stops silently dropping accents and CJK**. Auto and Clipboard paste
**keep a copied rich clipboard on X11**, and a prompt hotkey result **no
longer lands in a window focus moved to**. Also fixed: first-time **Gemma 4
model downloads**, **AssemblyAI** running a different model than the one
selected, **Transform Selection** rewriting text after hearing only
`[BLANK_AUDIO]`, and the recording overlay on **Openbox workspaces**. The
local API now gives **clear errors for translate requests and provider
failures** instead of a generic HTTP 500.

**Upgrade notes:**

- **Gemma 4 (Local): Save no longer downloads the model** (#285). Pick a
  model, click Save, then click the new **Download and load model** button.
  It shows progress, can be cancelled, and resumes a partial download. A
  model that is already downloaded still loads on first use after Save.
- **Direct typing with only ydotool on Wayland no longer types non-ASCII
  text** (#291). ydotool can only type the US keymap and dropped the rest
  while reporting success. If wtype (or xdotool on X11) can't type the text
  either, TypeWhisper now copies it to the clipboard without pasting, says
  so, and History records CopiedToClipboard. Paste with Ctrl+V, or switch
  the app to Auto or Clipboard paste. Spoken commands on such a chain insert
  the finished result instead of streaming it.
- **Hyprland: wtype is skipped for XWayland windows** (#284). ydotool types
  and pastes there instead. With wtype as the only backend, Auto copies the
  text to the clipboard and suggests setting up ydotool, and Direct typing
  fails instead of typing garbage. When ydotool is usable, the paste
  shortcut now goes through ydotool first on every Wayland compositor,
  because GTK3 apps ignore wtype's Ctrl+V.
- **hyprlock and other lockers that don't report their state** (#278): the
  hotkey stays blocked for about 3 seconds after a lock request, then comes
  back while the screen is still locked. GNOME and KDE keep the hotkey
  blocked for the whole lock as before.
- **Local API status codes** (#287, #288). A translate request to an engine
  that can't translate now gets `400 {"reason":"translation_unsupported"}`
  before any audio is uploaded. Before, it got a 500 or a silent,
  untranslated transcription. A provider failure on `/v1/transcribe` and
  `/v1/transcribe/local-file` now returns 503 (`provider_unavailable`,
  `provider_rate_limited`, `provider_not_configured`) or 502
  (`provider_authentication_failed`, `provider_rejected_request`,
  `provider_failed`) with the provider's message, instead of
  `500 Internal server error`.
- **Built-in prompt and profile names follow the interface language**
  (#302), including the prompt names spoken commands match against.
  Names you renamed yourself are kept. History records now store the
  profile id, so retrying a dictation still finds its profile after a
  rename; older records still match by name.
- **The Recorder reports `saving` as soon as a stop is accepted** (#297),
  with the duration frozen, instead of `recording` until the WAV is written.
  The Record button switches back at the same moment.

## Fixes

### Dictation and text insertion

- **wtype typed garbage into XWayland apps on Hyprland** (#284). XWayland
  ignores the keymap wtype uploads, so "QA abc 123" arrived as
  "123452678", its Ctrl+V was dropped, and History still said Typed or
  Pasted. The focused window is now checked with `hyprctl activewindow`
  before wtype runs; see the upgrade note for what happens instead. In
  native-Wayland GTK3 windows, Auto used to report Pasted with an empty
  field because GTK3 drops wtype's Ctrl+V; the paste now goes through
  ydotool when it's available.
- **Direct typing dropped accents, dashes and CJK on ydotool-only Wayland**
  (#291). "Front, QA café naïve — mañana, früh. 日本語テスト!" arrived as
  "Front, QA caf nave  maana, frh. !" and History said Typed. That text is
  now copied to the clipboard with a notice (see the upgrade notes). ASCII
  text and Auto are unchanged.
- **A rich clipboard was replaced after Auto and Clipboard paste on X11**
  (#294). If you had copied formatted text (for example HTML from a
  browser), the clipboard held only the dictated text afterwards. TypeWhisper
  now captures every format (up to 16 MB) before pasting and restores them
  all afterwards. The restored clipboard is owned by TypeWhisper until
  something else is copied or the app quits, unless a clipboard manager
  keeps it. Wayland (wl-copy) serves one type only and is unchanged.
- **Prompt hotkey results pasted into the window focus moved to** (#286).
  Running a saved prompt from its hotkey and clicking into another window
  while the LLM worked pasted the result there. The hotkey now records the
  compositor's window and checks it again before pasting, like dictation
  does; if focus moved, the result is copied to the clipboard with a
  warning.
- **Transform Selection rewrote text when whisper heard nothing** (#283).
  Quiet or very short command audio could transcribe as `[BLANK_AUDIO]` or
  `[Music]`, which was sent to the LLM as the command and the answer
  replaced your selection. A command made only of bracketed non-speech
  markers is now treated as empty: you get "The transform command returned
  no text." and the selection stays. "make it [bold]" still goes through.
- **Correction learning missed fixes typed right after dictation** (#301).
  In native-Wayland Firefox, wtype could return before the trailing space
  landed, so the corrected span was never found. Learning also stopped after
  you clicked Undo on the learned toast, because its button took AT-SPI
  focus. Both are fixed.
- **Screen reference sent nothing from Firefox textareas** (#295). The
  focused-field lookup used a match rule at-spi2-atk never matches, so the
  harvest fell back to a 40-node walk that Firefox's browser chrome used up.
  The focused textarea is now found in one call.

### Hotkeys, audio and recording

- **Global hotkey dead after unlocking hyprlock** (#278, fixes #232).
  hyprlock never sets logind's `LockedHint` or calls `unlock-session`, so a
  `Lock` signal blocked input for good until a restart. TypeWhisper now
  re-reads `LockedHint` 3 seconds after a lock request and re-enables input
  if the locker never confirmed it. Every block and enable is logged.
- **A microphone removed mid-recording froze the app** (#282). Unplugging a
  USB mic, a Bluetooth headset dropping, or a setup with
  `node.dont-fallback` left TypeWhisper stuck in Recording, with the window
  and the CLI unresponsive. `Pa_StopStream` looped forever in ALSA xrun
  recovery. The capture stream is now aborted instead, which returns
  immediately and keeps the partial recording.
- **The Automatic microphone preview reopened its stream in a loop** (#290).
  Opening and closing the preview's own stream emitted the `pactl subscribe`
  event that triggered the next reopen, 13 streams in 5 seconds on
  PipeWire. Only default-source changes and devices being added or removed
  now trigger a reopen.
- **Audio ducking restored old volumes onto other apps' streams** (#298).
  After a PulseAudio or PipeWire restart during dictation, a new stream
  could get a ducked stream's id and receive its old volume. Ducking now
  records the audio server's cookie and drops saved volumes from an earlier
  server.
- **`pactl subscribe` outlived the app after SIGTERM** (#293). One leaked
  per `kill` or logout in Automatic microphone mode, since .NET 10 no
  longer raises `ProcessExit` on SIGTERM. A SIGTERM handler now stops it.
- **The Recorder API said `recording` past the one-hour cap** (#297) for the
  10–45 s it took to finalize the WAV, with the duration still climbing.
  It now reports `saving`. A pause that fails to finalize now ends the
  session as failed and releases the microphone, instead of later saving a
  "completed" recording with that segment missing.

### Windows and overlays

- **Recording overlay missing on other Openbox workspaces** (#292). The
  overlay, live text window and learned-correction toast stayed on the first
  workspace under window managers without `_NET_WM_STATE_STICKY`. They now
  also ask for all desktops through `_NET_WM_DESKTOP`.
- **Learned toast on the wrong monitor for `GDK_SCALE=2` GTK apps on X11**
  (#299). GTK reports scaled field positions, so a field on the right
  monitor looked like it was on the left. The toast now checks the position
  against the window's real frame from xdotool and anchors to the window
  when they disagree.
- **Learned toast spilled onto the next monitor after Undo** (#296). The next
  toast was positioned with the narrower Undo confirmation's width. It now
  uses the freshly measured size.

### Interface language

- **Switching the interface language left text behind** (#302). Generated
  names, wizard choices, vocabulary pack headings, plugin editors, setup and
  status messages, microphone test results, the Automatic microphone label,
  backup and export results, file-picker titles, helper windows,
  accessibility labels and local provider names (whisper.cpp, sherpa-onnx)
  now follow the selected language, and so do Speechmatics' language
  choices and Obsidian's default note title and filename template. Unsaved
  plugin settings and prompt or profile drafts survive the switch, and long
  translated labels truncate with a tooltip.
- **Dictionary badges stayed English** (#280). Term/Correction and
  "Priority 2" now read, for example, Begriff/Korrektur and "Priorität 2".
- **Browser URL setup and revert results started in English** (#281). The
  status after Enable or Revert, the confirmation dialogs' step lists, and
  the revert summary of removed launchers and cleaned profiles are now
  translated, and a shown result rewords itself when you switch language.

### Providers, plugins and settings

- **Gemma 4 model downloads timed out on Save** (#285). Save waited for the
  whole multi-gigabyte download, hit the host's 5-second limit, and left a
  partial file with "Settings could not be saved". Downloading now has its
  own button; see the upgrade notes.
- **AssemblyAI ran a different model after saving its settings** (#300).
  The open settings panel kept the model from when it was opened, so Save
  could switch the engine to Universal-3.5 Pro while Settings, `/v1/status`
  and the Default model still said Universal-2. The Plugins page now
  re-reads the open plugin's settings when shown (unsaved edits are kept),
  and the next dictation reloads the model if a plugin changed its
  selection.
- **The spoken feedback provider couldn't be changed** (#289) when no
  system voice (espeak-ng, espeak or speech-dispatcher) was installed, even
  with Supertonic downloaded. The provider picker is now enabled whenever
  there is more than one provider, and the toggle and voice picker update
  as soon as you choose one.
- **Wrong advice for a non-UTF-8 Firefox `user.js`** (#279). Enabling
  browser URL detection told you to check the profile folder is writable.
  It now says the `user.js` isn't UTF-8, was left unchanged, and needs to be
  saved as UTF-8. A UTF-16 `user.js` is no longer counted as enabled, since
  Firefox can't read it.

### Local API

- **Translate requests on engines that can't translate** (#287). Smallest
  AI, Reson8, Cloudflare, Cohere and Gladia returned 500; Deepgram,
  Speechmatics, AssemblyAI, ElevenLabs and Google STT quietly transcribed
  without translating. All now get `400 translation_unsupported`.
- **Provider failures returned a generic 500** (#288). A provider that was
  down, a rejected key and a refused request all looked like a TypeWhisper
  crash. See the upgrade notes for the new status codes; the in-app API
  page lists them.

## Plugin SDK

- No SDK changes. Bundled plugins keep `minHostVersion` 0.19.0.
- Bundled plugin versions: Gemma 4 (Local) 1.1.2, Local Models (sherpa-onnx)
  1.2.1, Obsidian 1.0.2, Speechmatics 1.1.2, whisper.cpp (Local) 1.1.2.
  Every other bundled plugin is unchanged.

## Under the Hood

- The dictation pipeline tracks its phase directly, so CLI and API status
  no longer depend on translated overlay text, and status reports
  Transcribing while a prompt action or LLM cleanup runs (#302).
- A CodeQL alert for an implicit reference comparison on the Plugins page
  is fixed with `ReferenceEquals`; the compiled IL is unchanged (#303).

## Notes

- Not changed here: audio playback still calls `Pa_StopStream`, which can
  also hang if the output device disappears mid-playback (#282). XWayland
  detection is Hyprland-only, and with wtype as the only backend, native
  GTK3 windows still drop the paste shortcut undetected (#284). A server
  restart in the few milliseconds between ducking's cookie check and the
  volume change is still not covered (#298).
- Not verified on a live desktop in their PRs: the spoken-command path of
  #291, and the wider-root X11 case of #299.
- Failure messages from browser URL setup (they carry exception text) and
  the `(restored)` suffix on legacy restored launchers stay English (#281).
  Desktop file-dialog chrome follows the system locale (#302).
