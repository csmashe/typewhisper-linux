# TypeWhisper Linux v0.19.2

TypeWhisper Linux 0.19.2 adds opt-in **screen and clipboard reference
context** for Medium and High cleanup, so names and identifiers you can see
on screen or have copied come out spelled the way they are written. The rest
is fixes: **non-ASCII text that ydotool and xdotool silently dropped** in
browsers, terminals and streamed command results is now pasted, dictations
and spoken edits **no longer land in a window focus moved to**, the **local
API toggle no longer freezes the window**, and the **recording overlay and
floating live-text window keep the position you drag them to**.
**Ctrl+Alt+F1–F12 are refused as shortcuts**, because they switch the Linux
virtual terminal. Website profiles match **Unicode and punycode** domains,
browser URL detection reads the right tab and now works in **packaged
Firefox and Fedora's Chromium**, the **learned-correction toast follows your
monitor** on GNOME, a **new default microphone** is picked up while the
preview runs, and Gladia, Smallest AI, Qwen3 STT, OpenCode, GitHub Copilot
and the reported audio length of six engines each get a fix.

**Upgrade notes:**

- **Ctrl+Alt+F1–F12 can no longer be used as shortcuts** (#263), with or
  without extra modifiers. A saved main hotkey with one of them resets to
  Ctrl+Shift+Space at startup; a saved prompt, profile or secondary hotkey
  is skipped. Pick another chord if one of yours stops working.
- A spoken command no longer streams its answer chunk by chunk into
  browsers and Codex windows when the typing backend is **ydotool** (GNOME
  and KDE Wayland) or **xdotool** (X11); the whole result is inserted at
  once, so non-ASCII characters survive (#254, #274). Setting the app to
  **Direct Typing** brings streaming back.
- With **Close to tray** on, closing the window now quits the app when the
  tray host has gone away since startup, instead of hiding it with no way
  back (#267).
- The **Install Window Calls extension** button now opens Window Calls
  (extensions.gnome.org 4724) instead of Window Calls Extended (4974). Both
  give active-window detection; only Window Calls has the window geometry
  the learned-correction toast needs to find your monitor (#255).
- A dictation hotkey saved as **Ctrl+Shift+F9** is now kept at startup
  instead of being reset to Ctrl+Shift+Space (#238). If you never chose F9
  yourself, nothing changes.

## New

### Screen and clipboard reference context

- **Advanced → Reference context** has two new switches, **Use on-screen
  text** and **Use clipboard text** (#43, #235, #240). Before Medium or High
  cleanup, TypeWhisper reads a short snippet of the focused field and up to
  eight nearby labels through AT-SPI, and/or the current clipboard text, and
  gives it to the cleanup LLM as read-only spelling reference. The model
  uses it only to fix the spelling of words you already said, such as a
  colleague's name, a function name or a ticket number.
- Both are **off by default** and cost nothing while off. Capture runs only
  when a Medium or High cleanup with an available provider will actually
  run.
- **Password fields are never read**, whether focused or a neighbour. The
  screen read is limited to about a second, 40 accessibility nodes and 2,500
  characters, and the clipboard read is bounded the same way. With both on,
  the budget is split so each source keeps a share.
- The screen read only takes text from the window you were dictating into.
  Its title must match exactly (KWin's " <2>" suffix for duplicate titles is
  allowed), so a same-app window such as "Report private" next to "Report"
  is not read (#240). If the app has another window with the same title,
  nothing is read, since the title can't tell them apart (#266).
- Captured text is wrapped in a `<reference_context>` block with any
  closing tag inside it defanged, including forms with whitespace or other
  casing such as `</reference_context >`, so a page cannot end the block
  and add instructions (#235).
- Each profile has **On-screen Context Override** and **Clipboard Context
  Override** (Use global default, Enabled, Disabled). In browsers the
  capture waits for the URL match, so a website profile can turn a source
  off before it is read.
- With a cloud LLM provider, the captured text is sent to that provider.
  With prompt provenance capture on, History's **Inspect** panel shows it in
  the exact prompt.

## Fixes

### Dictation and text insertion

- **Non-ASCII text dropped when typed** (#242). On GNOME and KDE Wayland the
  typing backend is ydotool, which drops every accented, Greek or CJK
  character and still reports success. Auto insertion typed straight into
  browsers, terminals and Codex windows, so "Bonjour café Ω 東京." arrived
  as "Bonjour caf  ." and History said Typed. Auto now types there only when
  the text is ASCII or the typing chain can handle Unicode (wtype,
  xdotool); otherwise it pastes, with Ctrl+Shift+V in terminals. An
  explicit Direct Typing choice is unchanged.
- **The same on X11 with xdotool** (#274). On Cinnamon X11, Auto typing
  could drop the é in "café" in Firefox and in terminals such as
  gnome-terminal. xdotool is no longer trusted with non-ASCII text in Auto,
  so that text is pasted. xterm has no default paste shortcut, so there the
  text stays on the clipboard and the notice says so.
- **Streamed command results lost the same characters** (#254, #274).
  Streaming types each chunk as it arrives, before the whole text can be
  checked. With ydotool or xdotool in the chain, commands now insert the
  finished result in one go: non-ASCII results are pasted and ASCII results
  are still typed.
- **Results pasted into the window focus moved to** (#229, #268). On
  Wayland without xdotool, a dictation or spoken command that finished
  after you switched windows was pasted into the new window, and a spoken
  "shorten this" could replace text in an unrelated app. The window focused
  when recording started is now compared with the focused window right
  before auto-paste or auto-Enter; if they differ, the result goes to the
  clipboard. Spoken edits check the window before copying the selection, so
  another app's selection never reaches the AI provider, and cancel with
  "Edit canceled: focus moved to another window". With correction learning
  on, the focused field is checked too, so a result does not land in a
  different field of the same window.
- **Recent Transcriptions picks went to the clipboard on KDE** (#230).
  After the palette closed, KWin gave focus to TypeWhisper's main window,
  so the pick timed out and was only copied. TypeWhisper now asks KWin to
  re-activate the window the palette was opened over (`kdotool
  windowactivate`), and still falls back to the clipboard if that window
  can't be confirmed. If you moved to another app, focus is left alone.
- **Clipboard not restored after a paste on Wayland** (#218, #241). Plain
  text copied from a native GTK app on KDE (which lists `SAVE_TARGETS`) or
  from an Xwayland app on GNOME (which lists `TARGETS`) was treated as rich
  content, so the clipboard kept the dictated text. Both metadata targets
  now count as plain text; HTML, images and file lists still block the
  restore.
- **A failed capture stop left the session open** (#227). If stopping the
  audio capture threw, the session never finished: the API reported
  `in_progress` forever and History recovery stayed blocked. It now ends as
  `failed` with the usual failure feedback, and the next dictation works.
- **Memory extraction ignored your Default LLM** (#234). Extraction now uses
  the Default LLM's provider and model. If that default can't serve the
  request, extraction is skipped instead of going to a provider you didn't
  pick. With no default set, nothing changes.
- **A new default microphone was ignored while the preview ran** (#269).
  With the microphone following the system default, changing the default
  input during the level-meter preview or a microphone test kept recording
  from the old input. The preview now moves to the new default; a change
  during a recording applies to the next one, and a running microphone test
  ends with "device changed". Picking a microphone from the list also
  stays correct after the device list is renumbered.
- **A credit refusal sent twice** (#272). When a provider refused a prompt
  action with HTTP 402 (credits used up), or an authentication or
  permission error, the app retried the same request as a batch request.
  It now shows the error right away, and the warning dialog opens on top of
  the app you were in instead of behind it on GNOME.
- **False restore errors after audio ducking** (#264). When a ducked stream
  ended during dictation (a video player closed, say), pactl 16 on
  PipeWire reported it with different wording, and the app logged three
  restore errors. That case now counts as normal cleanup.

### Windows and overlays

- **Recording overlay snapped back after a drag on KDE** (#225). Avalonia's
  X11 move drag handed the pointer to KWin and ended TypeWhisper's drag
  before anything moved, so the new spot was never saved. The drop position
  is now saved once the overlay settles, a pause mid-drag no longer ends the
  drag, and the overlay reopens where you left it after a restart.
- **Floating live-text window forgot its position and size** (#251). The
  same X11 hand-off broke dragging and edge-resizing the window from
  **Appearance → Live text → Floating window**. Both are saved now.
- **Typing went nowhere after clicking Undo on the learned-correction
  toast** (#223). KWin kept the hidden toast as the active window. The toast
  is now marked as never taking keyboard focus; clicks still reach Undo.
- **Learned-correction toast on the wrong monitor on GNOME Wayland** (#255).
  Native Wayland apps give only window-relative field positions, so the
  toast used its bottom-center fallback on the primary monitor. With the
  Window Calls extension, it now reads the window's frame and Mutter's
  monitor layout (including scaled monitors) and shows under the window you
  corrected in. Without Window Calls, or with Window Calls Extended, it uses
  the old position.
- **Closing to a tray that had gone away** (#267). If the tray host went
  away after startup (a panel restart, say), closing the window still hid
  it, leaving no tray icon and no taskbar entry. The tray is checked again
  on close; without one, the app quits. The General page's tray hint
  follows too.

### Settings and setup

- **Turning off Enable local API froze the window** (#233, #248). Stopping
  the API on the UI thread deadlocked, and the switch kept showing On.
  Starting and stopping the API now runs in the background, so the window
  stays responsive even while a request is still running, and changing the
  port works the same way.
- **The welcome wizard opened on a blank "Step 0 of 6"** (#224). It now
  opens on step 1.
- **Shortcuts showed the old hotkey after the wizard changed it** (#245), and
  clicking Apply there bound the old chord again. The page now follows the
  saved hotkey without overwriting a chord you typed but haven't applied.
- **A taken hotkey was called unparseable** (#236, #252). In **Shortcuts**
  and in the wizard, a valid chord that another shortcut uses now says
  "'Ctrl+Alt+J' conflicts with another shortcut." instead of asking you to
  fix its syntax.
- **Ctrl+Alt+F1–F12 accepted as shortcuts** (#263). These chords switch the
  Linux virtual terminal; one saved as a prompt hotkey sent a QA machine to
  VT9. Every editor (Shortcuts, Profiles, Prompts, the wizard and the HTTP
  API profile toggle) now refuses them with "Ctrl+Alt+F1–F12 switch the
  Linux virtual terminal and can't be used as shortcuts.", and the desktop
  shortcut integration won't install one. A Prompt Palette chord that
  collides with another shortcut also says it conflicts instead of "Could
  not parse". See the upgrade notes.
- **Ctrl+Shift+F9 reset at startup** (#238). See the upgrade notes.
- **Dictionary add form out of reach** (#244). At 1280×800 the Original /
  Replacement boxes and **+ Add** were below the window with no way to
  scroll. The page now scrolls like every other settings page. At 800×600
  the entry rows ran their badges under the buttons and pushed **Delete**
  off the edge; narrow rows now stack (#262).
- **"No recordings yet." on a History search with no matches** (#259). It
  now says "No matching recordings." while history has entries.
- **History Read aloud failed silently** (#273). When the speech provider
  refused the request, the button just went back to **Read aloud**. The row
  now says "Could not read aloud. Check the speech provider and voice in
  Advanced." with the provider's error.
- **Snippets import without `Tags`** (#261). A file whose snippets left out
  `Tags` imported, then failed with "Object reference not set…" and left
  the list empty, also after a restart. Such snippets load now, including
  ones already saved that way.
- **Plugin settings showed every control twice after Validate** (#253), for
  example two API-key boxes in the Claude or Copilot card. Only the newest
  settings load renders now.
- **A failed Validate's error disappeared** (#250). The card rebuilt after
  Validate and reset its status to the default hint. The connection error
  now stays on screen.
- **Prompt provider picker crashed** (#247). Replacing a prompt's missing
  provider showed "Operation failed: Index was out of range" and didn't
  save. It saves now.
- **Silent import and export failures** (#214). Snippets import and export
  and History export now show an error dialog naming the problem when the
  file can't be read or written, or the snippets file is malformed.
- **Local model list binding errors** (#216). Expanding or collapsing the
  model list on **Dictation** logged binding errors; it no longer does.

### Profiles and browser URL detection

- **Website profiles and IDN domains** (#212). A profile saved as
  `xn--bcher-kva.test` didn't match `https://bücher.test`, and the other way
  round; both forms now match, including subdomains and `*.` wildcards.
  Browser URL capture also decodes Unicode addresses correctly, recognizes
  Chrome launched as `google-chrome`, finds the address bar faster, works
  in a freshly started Chrome on KWin and in Firefox's address bar, and no
  longer mistakes a URL-like field on the page for the address bar.
- **The previous tab's URL recorded after a tab switch** (#249). Two tabs
  with the same title shared one cached URL, so dictating in the second
  recorded the first one's URL and could apply the wrong website profile.
  Dictation now always reads the address bar, and drops the URL if the
  window or tab changed while it was being read. Only the Profiles page's
  live view uses the cache.
- **No URL from packaged Firefox, Fedora's Chromium or localhost** (#258).
  Mozilla's packaged Firefox runs as `firefox-bin` and Fedora's Chromium as
  `chromium-browse` / `chromium-browser`; neither was recognized as a
  browser, so website profiles never matched there. Both are now known. A
  local page shown as `localhost:19797/path` (no scheme, no dot) is also
  accepted as a URL.
- **Browser setup named no unwritable Firefox profile** (#239). If a
  profile's `user.js` couldn't be written, Profiles still said "Browser
  accessibility enabled." It now names the profile and says to fix its
  folder permissions and click **Enable browser URL detection** again.
- **A Firefox `user.js` lost its UTF-8 BOM** (#217) after setup and removal.
  The file now comes back byte for byte. Files that aren't UTF-8 are left
  alone and listed as not reverted, instead of being rewritten.
- **Profiles buttons clipped in a small window** (#246). At 800×600 the
  browser-setup buttons and **Install Window Calls extension** ran off the
  right edge or cut their labels. They now wrap.

### Providers and plugins

- **Gladia jobs left behind** (#213). Canceling a file transcription, a poll
  error or a timeout left the job and its transcript stored at Gladia. The
  job is now deleted in every case; while Gladia still reports it queued or
  processing, the delete is retried in the background for up to 30 minutes.
- **Smallest AI Pulse failed on Automatic** (#256) with "Language 'multi'
  has not been enabled in this region". Automatic now sends
  `language=auto`, and History shows the detected language.
- **Qwen3 STT put `<asr_text>` in the transcript** (#222) when a language
  was chosen (qwen3_asr_rs). The marker and the prompt text before it are
  removed, and the language you picked is reported.
- **GitHub Copilot rejected enabled models** (#228) with "The model … is not
  available to this account". The session now starts on the requested
  model, and the model is still checked against the bound account before
  any text is sent.
- **Wrong audio lengths** (#211, #237, #257, #260). Cohere, Gemini and
  Cloudflare's base `whisper` model reported 0 seconds for file
  transcriptions, because FFmpeg's piped WAV header has an unknown data
  size. Google Cloud STT reported billed time, rounded up to whole seconds,
  and local whisper.cpp reported where the last speech ended. All of them
  now report the measured length of the audio.
- **OpenCode without a saved credential** (#271) said "Login status cannot
  be checked safely". It now says there is no saved OpenCode Zen
  credential, and that keyless free use doesn't accept TypeWhisper's
  tool-free requests. OpenCode still needs a credential.
- **Parakeet CTC Vocabulary activated without its model** (#215). A
  `ModelDirectory` override missing `model.int8.onnx` now fails activation
  instead of reporting ready and failing on the first request.

### File transcription and the local API

- **Case-distinct files merged** (#210). Picking `Case.wav` and `case.wav`
  together queued only one; each now gets its own row.
- **Watch folder kept running after its path was cleared** (#265), still
  transcribing new files in the old folder. Clearing the path now stops it.
- **Subtitle cues out of order** (#221). SRT and VTT exports now list cues
  in start-time order when a provider returns segments out of order.
- **API `/docs` page** (#220). It now uses `typewhisper-cli` in its
  examples, points at **General → Services** for the switch, port and
  token, and explains how `language` and language hints combine for each
  request type.

## Under the Hood

- The settings default for the dictation hotkey is now Ctrl+Shift+Space,
  so fresh profiles and settings files without the key get the Linux
  default directly (#238).
- A shared native-drag guard covers Avalonia's X11 move and resize hand-off
  for the overlay and the live-text window (#225, #251).
- The shared atomic file writer keeps a UTF-8 BOM and refuses non-UTF-8
  files, which also covers the Hyprland and Sway shortcut writers and the
  CUDA profile setup (#217).
- The dictation composition test allows `kdotool`, `hyprctl` and `swaymsg`
  probes, so it passes on KDE, Hyprland and Sway (#219), and two Linux tests
  that raced under load are fixed (#243).
- Audio playback holds a PortAudio reference only while it owns a stream,
  so the capture side's device-table refresh actually rescans (#269).
- Three CodeQL alerts for always-true conditions and an implicit reference
  compare are fixed (#270).
