# TypeWhisper Linux v0.16.1

TypeWhisper Linux 0.16.1 is a maintenance release. It **replaces the retired
default Claude model** and lets the Claude plugin **load the models your
account offers**, **stops translate requests from silently returning
untranslated text** on Whisper models that cannot translate, makes **snippets
match whole words only** and never re-expand their own output, cleans up the
**punctuation after a spoken "new line"**, and **keeps transcripts from
OpenAI-compatible servers** that send malformed optional metadata. Most of it
was ported and adapted from upstream (`c2fcea53`); where the Linux port
deliberately differs, the notes say so.

Two things matter when upgrading: open the **Claude** plugin settings and
press **Validate** to load your account's model list, and translate tasks on
English-only (`*.en`) or Large V3 Turbo Whisper models are now refused with an
explanation instead of returning source-language text.

## New Features

- **Claude model discovery.** **Validate** in the Claude plugin settings now
  pages through the account's `/v1/models` catalog and saves it, using
  Anthropic's display names. If the account offers Sonnet 5 it goes first;
  otherwise the account's order is kept. A refresh that fails part-way, or
  returns an empty, malformed or endless catalog, is rejected whole and the
  saved list stays as it was. Changing the API key clears the saved catalog;
  a refresh still running when the key changes or the plugin is disabled is
  discarded and asks you to validate again. A rejected key (401/403) says
  "Anthropic rejected this API key"; other failures say why and that the
  saved list is unchanged.
- **Per-model translation support.** Whisper models now say whether they can
  translate: `tiny.en`, `base.en`, `small.en`, `medium.en`, `large-v3-turbo`
  and `large-v3-turbo-q5_0` cannot, every other catalog model can. The HTTP
  API's `GET /v1/models` reports this as `supports_translation` on each model
  (`null` for engines that do not declare it per model).

## Fixes

- **Claude's default model was retired.** Any prompt, translation or memory
  call that did not name a model used `claude-sonnet-4-20250514`, which
  Anthropic no longer serves. The built-in list is now Sonnet 5, Opus 5,
  Sonnet 4.6 and Haiku 4.5, and requests without a model use Sonnet 5. A
  request for a model that has since been retired (HTTP 404) now tells you to
  validate to refresh the list and pick an available model.
- **Claude replies are read correctly.** Non-streaming replies used only the
  first content block, so a leading thinking block, a tool call or an
  unfinished turn produced the wrong text or an unclassified error. Thinking
  blocks are now skipped and the text blocks joined; tool use, unknown blocks,
  an unfinished turn and a reply without visible text are reported as errors.
  Streaming replies reject refusal, tool-use and pause stop reasons and a
  stream with no visible text. Output-token limits now leave room for
  reasoning, as on upstream.
- **A prompt whose model the provider no longer offers** used to report "The
  selected AI provider is no longer installed". It now says that the provider
  no longer offers the selected model and to refresh its models or choose
  another one. The prompt is still refused before any request and never
  switched to a different model. This applies to every LLM provider.
- **Translate on a model that cannot translate.** A translate task on an
  English-only or Turbo Whisper model either did nothing or returned
  source-language text, which was then labelled as an English translation.
  It is now refused before the model loads, with a message naming the model:
  - **Dictation** saves the capture as a failed History entry with the
    reason, so **Retry** works once a model that can translate is selected. A
    profile hotkey that forces such a model is refused before the microphone
    opens.
  - **Live preview** stops polling the engine instead of failing on every
    poll.
  - **File transcription** is refused before the audio is decoded.
  - **The HTTP API and CLI** answer `400` with
    `"reason": "translation_unsupported"` before any download, decode or
    load.
  Engines that do not declare translation per model behave as before.
- **Snippets fire only on whole words.** Triggers matched inside other
  words, so a `link` snippet turned "hyperlink links" into "hyperURL URLs",
  and a snippet could fire on another snippet's replacement (`alpha → beta`
  plus `beta → expanded` turned "alpha" into "expanded"). Triggers now match
  complete words in the original transcript, longer triggers win where two
  overlap, and replacement text is never matched again. Word boundaries
  follow Unicode text elements, so accents, emoji and other combined
  characters are never split, and scripts written without spaces (Chinese,
  Japanese, Korean, Thai and similar) still match inside running text.
  Triggers that start or end with a symbol (`;sig`, `c++`, `[sig]`) work.
  Placeholders such as `{clipboard}` are only expanded, and usage only
  counted, for a match that is actually applied.
- **Punctuation after a spoken "new line".** A correction that turns a phrase
  into a line break only swallowed a period at the very end of the text, so
  "Hello new line. Next" became "Hello", a line break, and ". Next". It now
  consumes one following `.`, `,`, `;`, `:`, `!` or `?` anywhere in the
  text. A mark that belongs to the next word is kept (beyond upstream), so
  "new line .NET" keeps `.NET`. Ordinary corrections and regex corrections
  keep their punctuation.
- **Transcripts with malformed metadata are kept.** OpenAI Compatible, Groq
  and Qwen3 STT lost a valid transcript when the server sent `duration` or
  segment times as strings (GPUStack sends `"duration":"2.49"`) or any
  optional field as `null` or the wrong type. Only `text` is required now;
  numbers sent as strings are read in any locale, and invalid values fall
  back to defaults. A spoken segment whose silence probability was invalid
  no longer lets the "No speech detected" filter discard the whole
  transcript (beyond upstream).

## Plugin SDK

- `PluginModelInfo.SupportsTranslation` (`bool?`, init-only, default `null`):
  a catalog entry can declare whether the model translates, so the host can
  refuse a translate task without selecting or loading the model. `null`
  keeps the engine-wide `SupportsTranslation`.
- `OpenAiTranscriptionHelper` parses `verbose_json` leniently as described
  above; plugins that use it get the fix without a rebuild.
- The addition is init-only: plugins built against the previous SDK keep
  loading. The bundled whisper.cpp plugin now declares `minHostVersion`
  0.16.1.

## Under the Hood

- Compared with upstream, the Claude plugin keeps the Linux settings
  pattern (Validate fetches and saves the catalog) instead of upstream's
  Windows profile and settings-action SDK, and does not port upstream's
  per-plugin default-model and temperature settings. The catalog is saved
  before it goes live, so a failed settings write leaves the old list in
  place. Pagination is capped at 20 pages with a 60-second deadline.
- The host checks translation support in `ModelManagerService` from the
  model's declaration, after the profile settles and before any load. On
  Linux, unloading a model clears the selected model id, so an engine-wide
  check before loading was not possible.
- The CodeQL `cs/constant-condition` alerts in the CLI and the Claude plugin
  are fixed, and `cs/coupled-types` (the intentional History parent/row view
  models, mostly generated code) is excluded in the CodeQL configuration.
- Test suites at release: Core 1117, Linux 3016, Integration 74,
  PluginSystem 2700, Cli 197.

## Notes

- **Claude users:** press **Validate** once after upgrading to load the
  models your account offers. Until then the built-in list above is used.
  Prompts that name a model your account no longer offers report it instead
  of quietly using a different one; pick another model in Prompts.
- **Whisper translation:** to translate with whisper.cpp, choose a
  multilingual non-Turbo model such as `small`, `medium` or `large-v3`. Other
  engines are unchanged.
- **Snippets:** a trigger that relied on matching inside a longer word no
  longer fires there. The trigger-mode label still reads "Anywhere"; it
  means anywhere as a complete word.
