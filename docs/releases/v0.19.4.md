# TypeWhisper Linux v0.19.4

TypeWhisper Linux 0.19.4 is a fix release. **SIGTERM during a dictation
(logout, `kill`) now puts paused media and ducked volumes back**, and
**History retention no longer deletes a recording a kept entry still uses**.
Clipboard Paste and Auto **keep text copied from apps that only offer
COMPOUND_TEXT**, on X11 and on GNOME and Hyprland Wayland. On Sway, dictating
into a GTK3 app with only wtype **no longer reports Pasted while nothing
arrived**. With two Firefox instances open, the focused one **no longer
borrows the other one's URL, website profile and references**. Chromium
**intranet addresses like `qa-intranet:8080/page`** now match URL profile
rules, History only marks **screen and clipboard references applied when a
cleanup request actually carried them**, the About page **wraps long paths**,
and opening Plugins **no longer logs binding errors**.

**Upgrade notes:**

- **SIGTERM now quits the app like tray Exit** (#326). The app exits with
  status 0 when the quit finishes, instead of dying from the signal. If the
  quit hasn't finished after 15 seconds, the app restores audio and media
  itself and exits with status 143. A second SIGTERM still ends it right
  away. SIGINT and SIGHUP are unchanged.
- **Sway with wtype but no ydotool: native GTK3 apps get the clipboard
  instead of a paste** (#329). wtype's Ctrl+V never reaches GTK3 widgets, so
  the dictated text is now left on the clipboard, History records
  CopiedToClipboard, and a notice suggests setting up ydotool from
  Settings → Text insertion. Firefox, Chromium, Electron and Qt apps, which
  load GTK3 but handle shortcuts themselves, still get the wtype paste. An
  app whose process TypeWhisper can't inspect (for example in another user
  namespace) is treated as GTK3.
- **Browser URLs need to come from the focused browser instance** (#330).
  When the focused Firefox or Chromium window can't be tied to an app on the
  accessibility bus, the URL is now unavailable instead of read from another
  instance with the same name and title, and no URL is guessed from the
  window title in that case. On KDE, a window whose PID lookup through
  `kdotool getwindowpid` fails or times out gets no URL and no screen
  context. Flatpak browsers still get their URL.

## Fixes

### Audio and recording

- **Media stayed paused and other apps stayed quiet after SIGTERM** (#326).
  Logging out or running `kill` while dictating left the music TypeWhisper
  had paused paused and the streams it had turned down at the lower volume.
  The first SIGTERM now runs the normal quit, which restores both; see the
  upgrade notes. A duck or pause command that is still running when shutdown
  starts is waited for (up to 2.5 s), so the restore always comes after the
  last change. If a recorder or API drain fails during teardown, audio and
  media are still restored. The microphone watcher's `pactl subscribe` no
  longer outlives the app when SIGTERM arrives while the app is idle.
- **History retention deleted audio a kept entry still used** (#323). When
  an expired record and a newer one shared a recording, the startup purge
  deleted the file along with the expired record, and the kept entry lost
  its audio. Retention now uses the same reference check as Delete and Clear
  all: a recording is deleted only once no remaining record uses it.

### Clipboard and text insertion

- **The clipboard was lost when its owner only offered COMPOUND_TEXT**
  (#325). Text copied from some X11 apps read as empty, so after a Clipboard
  Paste or Auto dictation the clipboard held the dictated text instead of
  what you had copied. TypeWhisper now reads and decodes COMPOUND_TEXT
  (ISO 8859, GB2312, JIS X0208, KS C 5601 and UTF-8 segments) and restores
  it after the paste. On GNOME and Hyprland Wayland, where such an owner is
  bridged without a text type, the same fallback now runs when the read
  comes back empty or isn't valid text. Data the decoder doesn't understand
  still reads as empty, as before.
- **Sway reported Pasted when nothing reached a GTK3 app** (#329, fixes
  #309). With wtype as the only input tool, dictating into gedit or another
  native GTK3 app recorded Pasted, left the field unchanged, and restored
  the clipboard over the text. See the upgrade notes for what happens now.

### Browser context and profiles

- **A focused Firefox borrowed another instance's URL** (#330). With two
  Firefox instances on the same window title and only one of them on the
  accessibility bus, focusing the other one gave the dictation the first
  instance's URL, website profile and reference consent, and the screen
  context came from the background window. The text itself still went to
  the right window. The active-window snapshot now records the window's PID
  on X11, Hyprland, Sway, GNOME and KDE, and the URL lookup and the screen
  context harvest skip an app that belongs to a different instance of the
  same program.
- **Chromium intranet addresses were dropped** (#328). Chromium shows
  `http://qa-intranet:19837/page` as `qa-intranet:19837/page`, and a
  single-label host without a dot was rejected, so URL rules for it never
  matched. A host like that is now accepted when it has a port or a path. A
  bare word such as `weather` is still treated as search text.

### History

- **Screen and clipboard references were marked applied when cleanup never
  ran** (#327). With Medium cleanup and the reference switches on, turning
  off the LLM provider mid-recording made cleanup fall back to Light with no
  request, yet History still said the clipboard (and screen) references were
  applied. The flags are now set only after a cleanup request carrying them
  reached the provider. A request that reached the provider but failed, for
  example with HTTP 400, still counts; one that never connected (refused,
  DNS, TLS, proxy) doesn't.

### Interface

- **Long paths were cut off on the About page** (#324, fixes #304). A deep
  data folder or a long AppImage path ran past the edge of its box at the
  compact 960×640 window size. Both rows now wrap.
- **Opening Plugins logged binding errors** (#322, fixes #305). Each plugin
  card logged two `PendingAction` binding errors when no action was waiting
  for confirmation, 16 on a typical setup. The confirmation panel now
  renders only while an action is pending.

## Plugin SDK

- No SDK changes. Bundled plugins keep `minHostVersion` 0.19.0.
- No bundled plugin changed in this release; every plugin keeps its 0.19.3
  version.

## Under the Hood

- `TypeWhisper.Integration.Tests` loads the localization catalogs in a
  module initializer, so a test that reads localized overlay text no longer
  fails when it happens to run first (#331).
- These changes first landed as #310–#319 and were rolled back by #321
  because they were merged before QA finished. #322–#331 restore the same
  patches.
