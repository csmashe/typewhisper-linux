# TypeWhisper Linux v0.15.1

TypeWhisper Linux 0.15.1 brings **dictation recovery**, **more transcription and
LLM providers**, and **optional crash and performance reporting**. The provider
and recovery work was ported and adapted from upstream, with Linux integration,
request handling, and packaging fixes.

Highlights include retrying failed dictations from History, Microsoft MAI
Transcribe, Meta Muse transcription and Muse Spark, Gemini batch and live
transcription, and using signed-in provider CLIs for AI text processing.

Two defaults matter when upgrading: **Sentry reporting is off by default**, and
**dictation recordings are now retained locally for 30 days** so failed runs can
be recovered. Both are configurable; see the notes below.

## New Features

- **Recover dictations from History.** Failed transcription and processing runs
  appear with their status and a sanitized explanation when history saving is
  enabled. Use **Retry** while the recording is available to transcribe and
  process it again. A successful retry updates the existing entry and copies
  the result to the clipboard for you to paste. Retry uses the matching profile
  and current settings, so you can correct a provider configuration first.
- **Configurable recovery audio retention.** Under **Dictation → Recovery**, set
  **Keep dictation recordings for recovery (days)** to 1–365 days, or `-1` to
  delete captures when the app closes. The default is 30 days. Expired captures
  and recordings without a history entry are pruned at startup and shutdown;
  deleting a history entry also deletes its recording.
- **Optional Sentry reports.** **Advanced → Data → Send anonymous crash and
  performance reports** enables diagnostics for crashes, errors, startup, and
  dictation stages. **It is off by default.** We would appreciate you enabling
  it, especially if you are having issues, to help us diagnose failures and
  slowdowns across Linux setups. Turning it off stops reporting immediately.

- **Microsoft AI transcription.** The new plugin uses Azure Speech's fast
  transcription API with MAI Transcribe models. Configure an Azure Speech
  endpoint or resource name and API key, choose Clean or Verbatim transcript
  style, and optionally enable speaker diarization. MAI Transcribe 2 is the
  default, with 1.5 available as a fallback. **Validate** checks the connection
  and refreshes the model catalog. This provider uses batch transcription.
- **Meta transcription and LLM processing.** Use Muse Voice Transcribe for
  uploaded audio and real-time dictation, including optional speaker labels,
  language hints, and dictionary keywords. Muse Spark is available for LLM
  text processing with a reasoning-effort setting. Configure a Meta API key
  and use **Validate** to refresh both model lists.
- **Gemini transcription and live dictation.** The existing Gemini plugin now
  also supports `gemini-3.5-transcribe` and its live counterpart, with Smart and
  Verbatim modes, ordered language hints, and dictionary vocabulary. Batch
  transcription uploads audio through Google's Files API and attempts to
  delete the upload after processing. Transcription models are discovered
  alongside the existing LLM catalog.
- **Authenticated CLIs.** A new bundled plugin exposes installed, signed-in
  Codex, Claude Code, and OpenCode CLIs as LLM providers without entering an
  API key in TypeWhisper. Install and sign in from a terminal, enable the
  plugin, then use **Validate** to check installation, capabilities, and login
  status. OpenCode exposes only models in its currently verified free Zen
  catalog. Provider CLIs are installed separately from TypeWhisper.

## Fixes

- **Bounded retries for temporary LLM failures.** Cleanup and prompt processing
  can retry classified transient network, timeout, rate-limit, and server
  failures up to twice. Retry delays honor the provider's hint up to five
  seconds. Streaming retries stop once output begins; a batch compatibility
  attempt remains available before output for eligible stream failures.
- **Selected providers are respected.** An explicitly selected LLM provider
  that is missing, disabled, signed out, or otherwise unavailable produces a
  configuration error naming that provider. Processing does not silently move
  to a different provider. Required prompt actions fail; optional Medium/High
  cleanup can still return its Light cleanup result.
- **No extra batch request after a non-retryable failure.** Authentication,
  permission, and explicitly non-transient server errors no longer trigger a
  batch fallback. Stream-specific request-shape and unclassified failures can
  still use compatibility fallback before any output arrives.
- **Recovery preserves existing text.** A failed retry retains text already in
  the entry. Retry and live dictation cannot overlap, and cancellation stops
  recovery work. Failed entries stay out of successful-result exports, API
  history listings, and the recent-transcriptions palette.
- **Safer failure reporting.** Provider failures use shared classifications;
  displayed and logged failure messages redact sensitive content. A faulty
  history listener no longer prevents the remaining listeners from updating.
- **Consistent RPM metadata.** RPM packages use release `1` across build
  distributions, keeping package metadata, filenames, and validation aligned.

## Plugin SDK

- `ITranscriptionEngineRole.StartStreamingWithLanguageHintsAndPromptAsync`
  supplies ordered hints and prompt context to live transcription. Its default
  implementation preserves existing plugins' language-hint path.
- `IStreamingSessionHealth` exposes an optional thread-safe session fault so
  hosts can detect failures that arrive after finalization returns.
- Process supervision adds stdout/stderr byte limits and an option to clear
  the inherited environment, with explicit output-limit and truncation results.

## Under the Hood

- **CLI execution.** Provider tools run non-interactively with tools disabled,
  structured input/output, output limits, timeouts, and cancellation handling.
- **Sentry diagnostics.** Desktop packages include portable debug symbols for
  file and line numbers. Reports have no offline disk cache; disabling consent
  discards queued reports. Tag-triggered releases create and finalize a matching
  Sentry release with commit information after successful publication.
- **Regression coverage.** Tests cover recovery retention and retry outcomes,
  provider selection, request budgets, streaming behavior, CLI execution, and
  telemetry filtering and consent.

## Notes

- **What Sentry receives when enabled.** App version and install kind, OS and
  hardware details, engine/model names, error types and stack traces, timing
  data, audio duration, and transcript character count. Reports exclude audio,
  transcript and prompt text, clipboard contents, window titles, API keys,
  exception message text, and persistent user/install identifiers. See the
  [Privacy Policy](https://github.com/csmashe/typewhisper-linux/blob/linux/docs/PRIVACY.md)
  for the full details. Reporting remains **off until you enable it**.
- **Recovery stores local audio.** Recovery requires a saved history entry and
  its WAV capture. History retention and recording retention are separate;
  retaining text longer does not retain expired audio. Recordings under
  `Audio/dictation-*.wav` are excluded from settings backups.
- **Provider data flows are separate from Sentry.** Cloud transcription sends
  audio to the chosen provider. Authenticated CLIs may send prompts and text to
  their provider using your account. Some free OpenCode Zen models may permit
  training on inputs and outputs; check the selected model's terms before
  sending sensitive content.
- All new interface strings are translated across **English, German, Spanish,
  and Russian**.
- **Included scope.** PRs #84, #87, #88, #89, #90, #91, and #92, plus the retry
  correction and Sentry release workflow. Screen/clipboard reference context
  (PR #43) remains deferred.
