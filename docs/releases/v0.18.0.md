# TypeWhisper Linux v0.18.0

TypeWhisper Linux 0.18.0 makes local transcription crash-safe, cloud
providers more dependable, and **opens the main window in under a second**
(it took over 4 s). **whisper.cpp and Sherpa-ONNX now run in a
separate worker process**, so a native crash, a GPU driver abort or an
out-of-memory kill no longer takes the app down. The request is retried
instead. **Dictionary terms now reach eight cloud engines whole** (OpenAI,
Gemini, Gladia, Speechmatics, Cloudflare Whisper Turbo, and, if you opt in,
ElevenLabs and AssemblyAI) during dictation, not only through the HTTP API.
Live dictation with **Gemini, Gladia, Soniox, Meta and xAI** now finishes only
when the provider confirms the whole transcript, and otherwise falls back to
transcribing the recording. Quiet recordings no longer lose text with
**Parakeet**.

New in the app: a **Test microphone** button, a **Paste last transcription**
shortcut and tray item, **per-profile memory recall** with a File Memory
editor, an opt-in **local diagnostic log**, a content-free **support report**,
and **Export All Data**. Provider additions: **AssemblyAI Universal-3.5 Pro**
and speaker labels, **Speechmatics Standard**, regions and automatic language,
**Cloudflare Whisper Turbo**, account model discovery for **Cerebras** and
**Fireworks**, and **separate sessions of the authenticated CLIs**.

Most of it was ported and adapted from upstream TypeWhisper (`c2fcea53` and
later fixes). Where the Linux port deliberately differs, the notes say so.

**Upgrade notes:** saved AssemblyAI `universal-3-pro` selections move to
Universal-3.5 Pro. Linear users should press **Validate** once to load their
teams and projects. Several bundled plugins now require this version of the
app (see [Plugin SDK](#plugin-sdk)).

## New Features

### Dictation and the app

- **Microphone test.** **Dictation → Microphone → Microphone test** has a
  **Test microphone** / **Stop test** button. It names the device under test
  and reports in plain words: waiting for input, **No audio received**, **The
  microphone sends only silence** (every sample is zero, usually a mute),
  **Only background noise so far**, or **Audio signal received**. It stops
  after 15 seconds, when you leave the page, change the input device, the
  system default device switches, or dictation starts. It reads level frames
  only. Nothing is recorded, saved or sent. Each test reopens the input, so
  a microphone that was unplugged and plugged back in is found again.
- **Paste the last transcription again.** A new **Paste last transcription**
  shortcut (**Shortcuts**, unassigned by default) and the tray items **Paste
  Last Transcription** and **Copy Last Transcription** insert your latest
  transcription again. They add no History entry and make no LLM call. The
  shortcut fires when the whole chord is released, so the paste is not
  combined with modifiers you still hold. Terminals get Ctrl+Shift+V, and
  multiline text is never typed line by line. From the tray, the text is
  pasted only into an identified app; otherwise it is copied to the
  clipboard. It is refused with a message while a dictation, transform or
  prompt action is running or the recorder holds the microphone.
- **Memory recall per profile.** **Profiles → Memory Recall** offers **Use the
  global memory setting** (the default, so nothing changes), **Off**, or one
  specific memory source. A chosen source is the only one asked, even when
  global memory is off. If it is unavailable or its search fails, the prompt
  action fails and the dictation is kept in History. The choice applies to the
  profile's prompt actions, spoken commands and its "process selected text"
  hotkey. The prompt palette and global action hotkeys follow the global
  setting. Every recall now returns at most five facts (it was ten) of at
  most 1,600 characters each, and the LLM is told they are reference data,
  not instructions.
- **File Memory editor and better recall.** The File Memory plugin card now
  lists every remembered fact with a search box, and you can add, edit and
  remove them. Recall ranks facts by the words they share with what you said.
  Before, a fact was returned only if it contained the entire dictation, so
  prompt actions almost never received any. A new **Remember in File Memory**
  action target saves a prompt action's output as a fact.
- **Local diagnostic log (opt-in).** **Advanced → Data → Keep a local
  diagnostic log** records each dictation's steps, timings, engine and model
  names, outcomes and error types to
  `~/.local/share/TypeWhisper/Logs/diagnostics.jsonl`, so you can attach it to
  a support request. It is off by default and independent of crash reporting.
  It never contains audio, transcripts, prompts, clipboard contents, window
  titles, file names, API keys or error messages. Unknown fields are dropped
  when an entry is written, pruned and exported. It is never sent anywhere
  and is not part of settings backups. Choose **Keep entries for** 1, 3, 7
  (default), 14 or 30 days. The file is capped at 2 MB. **Export log…** and
  **Delete log** are next to it, and turning the log off deletes it.
- **Support report.** **About → Support Report → Export Report** saves a JSON
  description of the app's current state: app and system versions, desktop
  session, microphones (numbered, without names), engine, model and plugin
  readiness, profile and prompt metadata, behaviour settings, data counts, and
  the diagnostic log entries if that log is on. It never includes audio,
  transcripts, prompts, names, file paths, API keys or error messages. Model
  IDs from OpenAI-compatible servers, scripts and third-party plugins are
  omitted. Collecting it loads no model, activates no plugin and makes no
  network call.
- **Export All Data.** **About → Settings Backup → All Data → Export All Data**
  writes one `.zip` of everything TypeWhisper keeps in its data folder:
  settings, history, dictionary, profiles, snippets, prompt actions,
  statistics, plugin settings, logs and, unless you clear **Include
  recordings**, recordings. It contains a settings backup that **Restore**
  accepts, a manifest and a plain-text README. API keys, the protection key,
  plugin secrets and legacy webhook headers are removed from every settings
  copy. Models, runtimes, installed plugins and files TypeWhisper did not
  create are left out and listed. The archive is written owner-only and
  replaces the destination only once it is complete.

### Transcription engines

- **Local engines run in a recoverable worker.** whisper.cpp and Sherpa-ONNX
  now load models and transcribe in a separate process
  (`typewhisper --transcription-worker`). If it crashes, the request is
  retried in a new worker, up to three attempts. After two crashes in a row on
  the graphics card, the engine switches to the CPU until you change the
  acceleration choice, and the status says so. After three it pauses for 30 s,
  and loading a model explicitly ends the pause. A worker that freezes is
  ended after an inactivity window. Cancelling a long decode returns in about
  a second. A transcription that still fails keeps its recording in History
  with **Retry**, as before. Set `TYPEWHISPER_TRANSCRIPTION_WORKER=0` to keep
  the engines in the app process for diagnosis.
- **Whole dictionary terms for more cloud engines.** 0.17.0 let engines take
  dictionary terms as a list. These now use it, on every path (dictation, live
  preview, streaming, History retry, file transcription and the HTTP API),
  so a term like `Washington, D.C.` stays one term:
  - **OpenAI:** GPT Transcribe and GPT Live Transcribe send terms in their
    `keywords` field. whisper-1, GPT-4o (mini) Transcribe and GPT Realtime
    Whisper get them as prompt text. Streaming sessions now carry the prompt
    too.
  - **Gemini:** `custom_vocabulary` for recordings and live sessions, up to
    100 terms.
  - **Gladia:** custom vocabulary for recordings and live sessions, up to 100
    terms.
  - **Speechmatics:** `additional_vocab` for recordings and live sessions, up
    to 100 terms of at most 6 words (Speechmatics ignores longer entries).
  - **Cloudflare Whisper Turbo:** sent as `initial_prompt`.
  - **ElevenLabs** (recordings) and **AssemblyAI** (recordings and live):
    sent as keyterms only if you turn on the new **Send dictionary terms as
    keyterms** setting. It is **off by default** because both providers charge
    extra for keyterms. Upstream turns it on for ElevenLabs.
- **AssemblyAI Universal-3.5 Pro and speaker labels.** The models are now
  **Universal-3.5 Pro** (default) and **Universal-2**. AssemblyAI no longer
  lists `universal-3-pro`, so saved selections move to 3.5 Pro. Each model
  lists the languages it supports. Live dictation now always names its model.
  Before, English sessions got AssemblyAI's default, Universal-3.6 Pro. A new
  **Label speakers** setting (off, extra cost) writes `Speaker A: …` lines for
  recordings and turns off live text.
- **Speechmatics Standard, regions and automatic language.** Choose
  **Speechmatics Enhanced** or **Speechmatics Standard**, and a **region** (EU,
  US or Australia; EU by default) that is used for recordings and live
  dictation alike. Recordings support **Automatic** language and report the
  detected language. Live dictation cannot detect the language, so a new
  **Live transcription language** setting is used when dictation runs on
  Automatic. It can be a bilingual pack such as `cmn_en`. Without it, the
  recording is transcribed after you stop.
- **Cloudflare Whisper Large V3 Turbo.** A second Cloudflare model that takes
  an explicit spoken language and dictionary terms. **Validate** now really
  checks the account and token. Before, it said "Remote validation is not
  implemented yet."
- **Detected language from Reson8 and Soniox live dictation**, and from Gladia
  finals, so the streaming detected-language path from 0.16.0 now works for
  them.

### LLM providers and action plugins

- **Separate sessions of the authenticated CLIs.** The Authenticated CLIs
  plugin has a **CLI profiles** list for further sessions of Codex, Claude
  Code or OpenCode, for example a second account. Each profile is its own LLM
  provider with its own session directory (`CODEX_HOME`,
  `CLAUDE_CONFIG_DIR` or `XDG_DATA_HOME`), status and model list. The
  built-in providers and their IDs are unchanged.
- **Cerebras and Fireworks load your account's models.** **Validate** now
  fetches the models your key can use, keeps the list with that key, and
  keeps the saved list if loading fails. Both get a **Temperature** setting
  (provider default, or custom 0–2; the default stays at 0.1). The retired
  default models are replaced by `gpt-oss-120b`.
- **Webhook: test messages and a delivery budget.** Each saved webhook has a
  **Send test message** action, and **Show recent deliveries** lists
  outcomes. All webhooks for one transcription share a 10 s budget and are
  sent in parallel. Before, a slow endpoint could hold the queue for minutes.
  A webhook is retried once, and only when the request certainly did not
  arrive. Redirects are not followed, so header secrets reach only the saved
  URL. The profile filter is now an explicit choice: **All profiles and
  dictation without a profile** or **Only the listed profiles**.
- **Linear: all teams and projects.** **Validate** loads every team and
  project (paged) and never creates an issue. The default project is a
  dropdown with **No project**. The list belongs to the key that loaded it.

## Fixes

- **The main window opens in under a second.** A warm start took over 4
  seconds, mostly on the UI thread. The local API host watched the whole
  working directory for config changes (about 2.8 s and ~355,000 inotify
  watches on `$HOME` for the app's lifetime; it now holds one). Keyboard
  discovery opened every input device, and each close waits about 0.44 s;
  it now reads the device descriptions from sysfs. Startup work now runs
  after the window appears, and bundled plugins deploy off the UI thread.
  For a moment after the window shows, a hotkey can arrive before plugins
  and the model have loaded.
- **Linear never worked.** The plugin sent personal API keys as
  `Authorization: Bearer`, which Linear rejects with HTTP 400. They are now
  sent as Linear documents. Issue creation is never retried, and if Linear
  does not confirm an issue, you are told it may still have been created
  instead of being invited to create a duplicate.
- **Fireworks never worked.** Requests went to Fireworks's control-plane URL,
  where chat and model listing return 404, so every request failed and
  Validate always reported an invalid key. They now go to
  `/inference/v1/…`.
- **Cerebras's default model no longer existed**, so requests without an
  explicit model failed.
- **Quiet audio truncated Parakeet transcriptions.** Parakeet (Ultra and TDT)
  decodes some chunks of quiet speech to nothing, and those chunks were
  dropped as silence. Quiet chunks are now raised to a usable level before
  decoding (at most 20×), and a non-silent chunk that still comes back empty
  is retried once at a higher gain. On 45 recent recordings, three that had
  been truncated were recovered and none got shorter.
- **Gladia live dictation always ran twice.** Gladia only sends its
  `end_session` event when asked, and TypeWhisper never asked, so every live
  dictation was transcribed again from the recording and billed twice. The
  event is now requested. Repeated finals are inserted once, and rejected
  requests and errors are reported instead of ignored.
- **Gemini live dictation could drop the last words.** It waited a fixed 1.5 s
  after the end of audio and treated quiet speech as silence. It now uses
  manual activity detection and completes only when Google confirms the final
  transcript covering all the audio sent. Otherwise the recording is
  transcribed.
- **Meta live dictation with speaker labels always ran twice.** Meta ends
  speaker-labelled sessions with a normal close, not a final transcript,
  which TypeWhisper treated as a failure. Malformed Meta responses and model
  lists are now rejected instead of read as empty.
- **xAI live dictation dropped and repeated words.** From the second
  utterance on, text before a pause could be lost and earlier text typed
  twice. Utterances are now settled once each.
- **Soniox live dictation** authenticates with a header. Sending the key in
  the start message stops working on 15 January 2027. It also moves to
  `stt-rt-v5`, as `stt-rt-v4` was retired. A session that ends before
  confirming its text now falls back instead of dropping that text.
- **Speechmatics recordings came back without spaces** (`hellothere.`). Words
  are now joined with the language's word delimiter and punctuation attaches
  correctly. Deleted and expired jobs fail at once instead of polling until
  the timeout.
- **Voxtral with an explicit language** sent `language` together with
  timestamp granularities, which Mistral does not support. An explicit
  language is now sent alone.
- **Reson8:** a failed custom-model refresh no longer wipes the list and
  resets your selection. Changing the base URL, auth header or key hides a
  list loaded for another connection. A network failure is no longer reported
  as an invalid key. Streamed previews can no longer wait forever for a flush
  confirmation.
- **Overlapping insertions.** Dictation, palette, prompt action and transform
  output could be inserted at the same time and restore each other's
  clipboard. Insertions now run one at a time. Text from the recent
  transcriptions palette now follows the per-app insertion rules too.
- **A recording that could not be saved lost its text.** If the WAV could not
  be written, the whole dictation failed. It is now transcribed from memory
  and delivered. That History entry has no audio to retry from.
- **Authenticated CLIs failed under umask 0002** (Ubuntu's default) when
  `XDG_RUNTIME_DIR` was unavailable, because plugin data folders were created
  group-writable and the plugin then refused them. They are now created
  owner-only.
- **Choosing another microphone** now moves the level meter to it right away.

## Plugin SDK

All additions are optional, and plugins built against the previous SDK keep
loading.

- `IStreamingSessionFinalizeTimeout.FinalizeTimeout`: a streaming session
  whose provider confirms the transcript only after the end of audio can ask
  the host to wait longer when finalizing a dictation. The host clamps it
  between its 2 s default and 30 s. Gemini asks for 15 s.
- `IWebSocketCloseAwareAdapter.HandleClose(status, description)`: an adapter
  whose protocol can end with a close frame decides whether that close
  completes the session, fails it, or keeps the pump's default fault.
- `PluginCollectionDefinition.IsSearchable` (default `false`): shows a filter
  box above a settings collection. Filtering only hides rows, and Save still
  sends every item.
- `WebSocketTerminalPolicy.None` has no in-tree user any more but stays in the
  SDK.
- `minHostVersion`: Gemini, Meta and File Memory need 0.18.0 for the
  interfaces above. OpenAI, ElevenLabs, AssemblyAI, Gladia, Speechmatics and
  Cloudflare ASR need 0.17.0 for structured dictionary terms. Webhook already
  needed 0.17.0.
- Bundled plugin versions: OpenAI 1.3.0; AssemblyAI, Gemini 1.2.0;
  Authenticated CLIs, Cerebras, Cloudflare ASR, ElevenLabs, File Memory,
  Fireworks, Gladia, Linear, Reson8 and Speechmatics 1.1.0; Webhook 2.1.0;
  Meta and Sherpa-ONNX 1.1.1; xAI 1.1.2; Soniox 1.0.6; OpenAI Compatible
  1.0.5; Voxtral 1.0.1.

## Under the Hood

- The transcription worker talks to the app over a private Unix socket with
  framed JSON. The app accepts exactly one peer, checks it with `SO_PEERCRED`
  and a launch token, and ends the worker's whole process group when it
  exits. The worker gets a read-only copy of the plugin's settings without
  secrets. Model downloads, removal, settings and CUDA provisioning stay in
  the app. CTC, TTS and local LLMs still run in the app process.
- Package smoke tests check that every package format reaches the worker
  entry point.
- Webhook, Linear, Reson8 and Cloudflare no longer follow redirects, so saved
  credentials never reach another host.
- Live-session provider errors from Soniox and Gladia are classified by
  status code (authentication, permission, rate limit, …). Their messages
  are built from named fields only and never echo the raw payload.
- The host's 2 s finalize budget still applies to every other provider. If
  Gladia's post-processing takes longer, dictation falls back to the
  recording.
- Retention skips rewriting the history when nothing has expired, and usage
  statistics read the history only while their one-time backfill is pending.
- Test suites at release: Core 1213, Linux 3234, Integration 80,
  PluginSystem 3462, Cli 197.

## Notes

- **AssemblyAI:** saved `universal-3-pro` selections in the plugin and in the
  global, file and watch-folder model settings move to Universal-3.5 Pro.
  Profile overrides keep the old ID, which still maps to 3.5 Pro.
- **Linear:** team and project lists from earlier versions are not tied to a
  key and are ignored. Press **Validate** once to load them again. Until
  then, saved IDs show as raw IDs.
- **Cost:** ElevenLabs and AssemblyAI keyterms stay off until you enable them.
  Gemini, Gladia, Speechmatics, OpenAI and Cloudflare Turbo now receive your
  enabled dictionary terms with every transcription. None of them lists a
  surcharge for it. Disable a term in the Dictionary to keep it out.
- **Speechmatics live dictation on Automatic** needs the new **Live
  transcription language** setting. Without it, the recording is transcribed
  after you stop.
- **Webhooks:** existing files keep their meaning (a non-empty profile list
  means "only the listed profiles"). URLs with a user name or password in
  them are now refused.
- **Not verified against the live APIs:** most provider changes in this
  release were built from the providers' documentation and upstream's live
  checks, without keys for OpenAI, ElevenLabs, AssemblyAI, Gemini, Gladia,
  Speechmatics, Soniox, Reson8, Meta, xAI, Voxtral, Cloudflare, Cerebras,
  Fireworks or Linear. Please report anything that misbehaves.
