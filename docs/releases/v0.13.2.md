# TypeWhisper Linux v0.13.2

TypeWhisper Linux 0.13.2 is a **maintenance release**. It ports the shared bug
fixes from upstream TypeWhisper v1.0.5 through v1.0.9 into the Linux tree, and
in each case where upstream's behaviour had a flaw for this fork, it takes the
better path and says so below. Nothing in it changes how you drive the app.

Three things are worth knowing about before you upgrade: **a cut-off LLM reply
now fails instead of being pasted as if it were complete**, **reasoning models
no longer leak their thinking into your text** — with a new per-endpoint
Thinking Mode control for OpenAI-compatible servers — and **Whisper's trailing
"Thank you." hallucination is stripped** when it sits on silence at the end of a
recording.

## Fixes

- **Truncated LLM responses are rejected, not pasted.** Every LLM request used a
  fixed 2048-token output cap and returned whatever came back, so a long prompt
  action could paste a cut-off rewrite as though it were finished. The output
  budget now scales with the prompt, from 2048 up to 4096 tokens, and a response
  that stopped at the token limit — an OpenAI-style `length` finish reason, an
  Anthropic `max_tokens` stop reason, or a Responses API `incomplete` status —
  raises a classified error instead of being accepted. The shared chat helper
  applies both on batch and streamed responses, so Cerebras, Cohere, Fireworks,
  Gemini, Groq, OpenAI, OpenAI-Compatible, and OpenRouter are covered at once;
  Claude, xAI, the OpenAI Responses and ChatGPT login clients, and the local
  Gemma runner carry their own checks. Cleanup falls back to Light cleanup as it
  always has; a prompt action or spoken command reports the failure. Deliberate
  differences from upstream: the ceiling is 4096 rather than 8192 because older
  models reject a cap above their output limit, OpenAI-Compatible keeps its fixed
  cap because a self-hosted context window is unknown, and xAI and the ChatGPT
  login backend send no cap at all because the first needs the headroom for
  reasoning tokens and the second rejects the field.

- **Reasoning output stays out of your text.** OpenAI-compatible chat replies
  that contain `<think>` blocks are stripped on both the batch and the streaming
  path, even when a tag is split across SSE frames, and a reply that contains
  only reasoning is reported as an error instead of inserted as blank text.
  Requests are serialized with Unicode kept literal, so non-ASCII prompts reach
  smaller servers intact. Groq's Qwen models get `reasoning_format: hidden` so
  Groq does not return the reasoning inline in the first place. OpenRouter's
  batch path now goes through the shared helper too.

- **Trailing "Thank you." hallucinations are stripped.** Whisper-family engines
  append a stock "Thank you." segment during trailing silence; the existing
  whole-transcript filter cannot see it because real text precedes it. The
  transcription helper shared by Groq, OpenAI, OpenAI-Compatible, and Qwen3 STT
  now reports each segment's `no_speech_prob`, and the host drops a terminal
  segment that is only a stock phrase with silence probability above 0.8. It
  honours the **Transcribe short quiet clips aggressively** setting like the
  other silence gates, and applies on the dictation, file-transcription, and
  HTTP API paths. Upstream stripped the segment inside the Groq plugin only.

- **Spoken-number normalization works when no language is reported.** Parakeet
  reports no language, and "auto" counts as no information; in both cases number
  normalization used to skip the text entirely. It now falls back to the English
  parser. Upstream tried every supported parser and kept the first that changed
  the text, which on this fork turned "the value is null" into "the value is 0"
  and Spanish "once" into "11"; the fork falls back to English only and leaves
  the text alone when a language is known but has no parser.

- **Soniox async transcription is faster.** The plugin uses the `stt-async-v5`
  model, polls with an adaptive delay that starts at 150 ms and backs off to 2 s
  instead of a fixed 1 s, and deletes the upload and transcription in the
  background after a successful transcript rather than on the critical path.
  Failure paths still clean up synchronously. Deactivation drains every pending
  deletion, including ones registered while it is already waiting, so uploaded
  audio never outlives the session — a gap upstream's version left open.

## New Features

- **Thinking Mode for OpenAI-Compatible endpoints.** Each endpoint, including
  every additional profile, gains a **Thinking Mode** setting with three
  choices. **Provider default** sends nothing, so strict servers are never sent
  an unknown field. **Off** and **On** send both the generic `thinking` control
  that cloud endpoints read and the `chat_template_kwargs.enable_thinking` form
  that vLLM and llama.cpp read; DeepInfra hosts get `reasoning_effort` instead.
  Upstream always sent the generic field alone, which vLLM and llama.cpp ignore.

## Plugin SDK

- `PluginRequestException` with a `PluginRequestFailureKind` (`OutputTruncated`,
  `OutputIncomplete`, and the transport kinds), `LlmOutputTokenBudget`, and
  `LlmResponseTruncationGuard` are new public helpers.
- `OpenAiChatRequestOptions` is a new record accepted by new
  `SendChatCompletionAsync` and `SendChatCompletionStreamingAsync` overloads. It
  carries the output-token floor, whether to scale it, the parameter name, the
  provider name used in error messages, reasoning effort, and provider-specific
  `AdditionalBodyFields`. A field that collides with one the helper manages is
  rejected rather than silently overwritten. The legacy overloads are unchanged.
- `PluginTranscriptionSegment` gains an optional `NoSpeechProbability`; the
  positional constructor is unchanged.
- The seven plugins compiled against the new API — Claude, Gemma Local, Groq,
  OpenAI, OpenAI-Compatible, OpenRouter, and xAI — now declare
  `minHostVersion: 0.13.2`, so an older host refuses them with an explanation
  instead of loading them and failing at runtime.

## Under the Hood

- **Local API.** The verbose `/v1/transcribe` response includes each segment's
  `noSpeechProbability` alongside `text`, `start`, and `end`.
- **CI.** Every workflow uses `actions/setup-dotnet` v6. The SDK version still
  comes from `global.json`; this is the action's release tag, not a .NET version.
- **Code quality.** The ReSharper inspection count at HINT severity is back to
  zero across the solution: the genuine findings are fixed and the subjective
  ones carry a suppression with a reason.

## Notes

- All new interface strings are translated across **English, German, Spanish,
  and Russian**.
- **Plugin versions.** Claude 1.0.1, Gemma Local 1.0.1, Groq 1.0.5, OpenAI
  1.2.1, OpenAI-Compatible 1.0.3, OpenRouter 1.1.2, Soniox 1.0.4, and xAI 1.1.1.
  The seven that depend on the new SDK API require host 0.13.2 or later.
- **Plugin authors** using `OpenAiChatHelper` should switch to the options
  overload if they need provider-specific body fields; keys the helper writes
  itself (`model`, `messages`, `stream`, `temperature`, `reasoning_effort`, and
  the output-cap parameter) throw `ArgumentException`.
- **Number normalization with an unreported language** now assumes English.
  If you dictate in German or Spanish through an engine that reports no
  language, set the language explicitly so the right parser runs.
- The trailing-segment strip only fires for engines that report per-segment
  silence probability today: Groq, OpenAI, OpenAI-Compatible, and Qwen3 STT.
  The bundled whisper.cpp engine already has its own silence handling.
