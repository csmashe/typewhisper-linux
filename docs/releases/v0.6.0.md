# TypeWhisper Linux v0.6.0

TypeWhisper Linux 0.6.0 is the streaming release. It threads real-time
streaming through the whole dictation and prompt pipeline: speech-to-text now
runs over a provider websocket so partial text appears in the overlay as you
speak, and LLM responses stream back token-by-token into the dictation overlay
and the prompt palette instead of arriving as a single block. The work spans a
new host-side streaming subsystem, websocket sessions for several cloud
transcription providers, and a token-streaming contract added to the plugin
SDK with a per-provider opt-out toggle.

## New Features

- Added real-time websocket live transcription. A new
  `StreamingTranscriptionCoordinator` drives a streaming session against the
  active provider, and `AudioRecordingService` now feeds audio to it in real
  time so partial transcripts surface in the overlay as you talk. This replaces
  re-uploading the whole growing buffer on every poll — audio chunks are sent
  once, and latency drops from the multi-second poll cadence to the hundreds of
  milliseconds.
- Taught `LinuxLiveTranscriptionStartupPolicy` a `Streaming` arm. When the
  active engine reports `SupportsStreaming` and the user has enabled live
  streaming (`LiveTranscriptionStreamingEnabled`), streaming is chosen ahead of
  the batch polling preview; otherwise the existing polling / on-device preview
  behavior is unchanged.
- Added websocket streaming sessions for the cloud transcription providers:
  Gladia, Soniox, Speechmatics, and xAI, plus an OpenAI GPT Realtime Whisper
  streaming session. Together with the existing AssemblyAI, Deepgram,
  ElevenLabs, Smallest AI, and Reson8 sessions, ten cloud engines can now feed
  live partial text.
- Added the xAI streaming stack — `XaiStreamingSession` and a dedicated
  `XaiResponsesClient` for the Grok Responses API.
- Added token-by-token LLM response streaming. The SDK's `ILlmProviderPlugin`
  gained `ProcessStreamingAsync`, a host-side `LlmStreamPump` accumulates and
  publishes deltas, and a new `LlmResponseTokenEvent` carries the running text.
  The default interface implementation wraps the existing batch `ProcessAsync`
  in a single yield, so providers that do not override it stay byte-identical to
  the non-streaming path.
- Streamed LLM output is now rendered live in the dictation overlay and in the
  prompt palette window, with mid-stream fault handling that flips to a terminal
  flush instead of leaving a half-written response on screen.
- Added a per-provider **Stream responses** toggle, keyed by the shared
  `LlmStreamingSettings.StreamResponsesSettingKey` so the setting key never
  drifts between plugins. It is opt-out (streaming is on when unset) and is
  exposed on every LLM provider: Claude, Cerebras, Cohere, Fireworks, Gemini,
  GemmaLocal, Groq, OpenAI, OpenAI-compatible, OpenRouter, and xAI.
- Added `IPostProcessorPlugin.ProcessStreamingAsync` so post-processing steps
  participate in the streaming contract. The default implementation yields the
  full result in one chunk; true per-token piping between pipeline steps is a
  deferred follow-up.
- Added a `RequireLlmSuccess` flag to the post-processing pipeline, so a failed
  LLM step can block insertion rather than silently passing through
  un-processed text.

## Improvements

- Extended the shared `OpenAiChatHelper` with a streaming chat-completion path,
  reused by the OpenAI-family LLM providers so streaming behaves consistently
  across them.
- Refactored the Gladia streaming API integration and tightened its error
  handling.
- Improved streaming-session lifecycle handling across the plugins (clean
  WebSocket open/close, cancellation, and fault propagation).
- Enhanced the Soniox plugin and refined the Reson8 streaming session alongside
  the new streaming sessions.
- Updated the Linux program to dispose services asynchronously on shutdown so
  in-flight streaming sessions tear down cleanly.
- Hardened secret trimming and error handling in plugins, and added WAV header
  size checks.
- Added extensive test coverage for the new surface, including
  `StreamingTranscriptionCoordinatorTests`, `LlmStreamPumpTests`,
  `PromptProcessingServiceTests`, streaming-default tests for the LLM and
  post-processor contracts, and per-plugin streaming tests for Claude, Gladia,
  Groq, OpenAI, OpenAI-compatible, OpenRouter, Soniox, Speechmatics, and xAI.

## Fixes

- Fixed a scroll issue with large partial transcription text in the dictation
  view.
