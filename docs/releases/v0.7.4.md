# TypeWhisper Linux v0.7.4

TypeWhisper Linux 0.7.4 is a tiling-window-manager fix release. It makes
dictation work end-to-end on wlroots compositors (Hyprland, Sway, …), where the
0.7.x onboarding work had only been exercised on full desktop environments: the
automatic-paste setup now completes instead of stalling, transcripts land in the
app you're actually focused on instead of TypeWhisper's own overlay, and a
desktop notification stands in for the floating overlay as the recording
indicator where a tile-reserving window doesn't belong. Audio cues are now
reliable regardless of your desktop sound theme, and several rendering and
race-condition papercuts are fixed. Hyprland (Wayland) is now a tested setup.
Nothing here changes behavior on GNOME or KDE — the overlay and existing flows
stay exactly as they were.

## Fixes

- **Automatic-paste setup no longer stalls on Wayland.** The one-click `ydotool`
  setup now loads the `uinput` kernel module and persists it across reboots
  (`/etc/modules-load.d/uinput.conf`) as part of the same admin prompt that
  installs the udev rule. On distributions that don't auto-load `uinput` (Arch
  and others) the setup previously installed everything correctly but the daemon
  had no device to open, so the task sat "in progress" and never went green. The
  setup message was also reworded so it no longer tells you to run a `systemctl
  enable` command that the app already handles.
- **Transcripts go to the focused window, not the overlay.** On Hyprland the
  active-window lookup could return one of TypeWhisper's own windows, so a
  dictated transcript was typed back into the app instead of the editor or chat
  box you were aiming at. The Hyprland window provider now filters out
  TypeWhisper's own process, so paste always targets the real foreground app.
- **Recording indicator on tiling window managers.** On wlroots compositors the
  floating overlay was the wrong primitive — as an XWayland toplevel it reserved
  a tile, stole focus from the dictation target, and blurred into an empty box.
  On those compositors the overlay is now suppressed and the recording state is
  shown as a persistent desktop notification ("🔴 Recording") with a mode-aware
  hint for how to stop, raised on start and dismissed on stop through the
  standard freedesktop notification service. GNOME, KDE, and Cinnamon are
  unaffected and keep the overlay.
- **Stuck "🔴 Recording" notification.** A rapid start→stop could finish out of
  order and leave the recording notification up forever. Each state change now
  carries a generation counter so the last edge always wins and the popup is
  reliably cleared.
- **Appearance settings now match your desktop.** On tiling window managers the
  Appearance tab no longer shows overlay-layout controls that don't apply;
  instead it explains the notification indicator and previews the exact body text
  for your recording mode. The preview also shows the real TypeWhisper icon
  rather than a blue placeholder box, and the activity-feed metadata (timestamp
  and app name) is no longer near-black on a dark background.
- **Reliable audio feedback.** Start, stop, success, and error cues now play from
  bundled WAV files through whichever PCM player is present (`pw-play` /
  `paplay` / `aplay`) instead of going through the desktop sound theme or
  libcanberra. Feedback no longer depends on a sound theme shipping the right
  named events or on the GNOME system-sounds toggle, and cancelling a recording
  now plays its own distinct cue rather than the success or error sound.
- **Overlay rendering on NVIDIA + XWayland.** Adjusted the overlay window so it
  renders correctly on NVIDIA under XWayland instead of showing artifacts.

## Not Ported From Windows

- Windows release channels and Velopack update-channel controls are not part of
  this Linux branch; the Linux app checks GitHub Releases for updates but installs
  them manually.
- Windows-specific workflow automation and packaging changes remain Windows-only.
