# TypeWhisper Linux v0.19.1

TypeWhisper Linux 0.19.1 is a maintenance release. It fixes **invisible
overlay windows that swallowed clicks** in the top-right corner on GNOME,
**file drops from other apps on X11**, **`--minimized` startup on a desktop
without a tray**, and the **Codex, Claude Code and OpenCode** providers in
Authenticated CLIs, which showed Ready but failed every request. It also
fixes **GitHub Copilot accounts** for anyone signed into the `gh` CLI,
**AssemblyAI streaming** sessions that faulted, **Transform Selection**
pasting into the wrong field, **media pause** with two instances of one
player, and a set of smaller profile, clipboard and subtitle bugs. The
**online plugin registry is removed**; it was never published, and the app
keeps shipping its plugins bundled.

**Upgrade notes:** the Codex CLI provider now needs **Codex 0.147 or
later**; older installs show the unsupported-version status instead of
Ready. Nothing else needs action.

## Fixes

### Desktop and windows

- **Clicks in the screen corner on GNOME** (#209). The hidden live text
  window, the dictation overlay and the learned-correction toast stay
  mapped while hidden, and Mutter clamped them back on screen, topmost, so
  clicks in the top-right corner of the right-most monitor went nowhere
  (for example a Files window's close button). While hidden they now empty
  their X11 input shape, so clicks pass through, and restore it before
  showing.
- **Drag and drop from other apps on X11** (#204). Dropping an audio file
  from Nautilus or another GTK app onto **File transcription** did nothing,
  because Avalonia 12.0 had no XDND support on X11. The app moves to
  Avalonia 12.1.4, which adds it. Native Wayland drag and drop was not
  tested.
- **`--minimized` without a tray** (#200). The autostart entry passes
  `--minimized`, and on a desktop with no StatusNotifier host the window
  was hidden with no tray icon to bring it back. The app now waits up to 10
  seconds for a tray host (panels often register after autostart); if none
  appears, the window comes back to the taskbar (minimized on GNOME and
  similar desktops, shown on Hyprland and Sway). A tray that appears late
  is picked up by close-to-tray and the General page. The setup wizard
  opens once, and only after the main window is visible.
- **Learned-correction toast on the wrong monitor on Wayland** (#208).
  Native Wayland apps report window-relative coordinates through AT-SPI,
  which were read as global, so the toast could land on an unrelated
  monitor. Those coordinates are now ignored and the toast uses its
  bottom-center position on the primary screen. XWayland apps and X11
  sessions are unchanged.
- **GNOME active-window detection with an apostrophe in a window title**
  (#206). Any open window titled like "owner's notes" made the Window Calls
  reply unreadable, breaking app profiles and URL context. Both GLib quote
  styles are now parsed.

### Dictation and text insertion

- **Transform Selection pasted into another field** (#202). Moving to
  another field in the same window while the LLM was working pasted the
  result there and still reported success. The selection is now copied
  again before replacing; if it changed, nothing is replaced, the result
  goes to the clipboard and a "Focus or the selection changed" warning
  shows. Works on X11 and Wayland without AT-SPI.
- **"Draft a message that says…"** (#201). Spoken commands like "Draft a
  message that says hello world" with nothing selected failed with "Nothing
  highlighted to edit", and "Write an email that says…" could validate a
  saved action's provider instead. A "that" after "a"/"an" no longer counts
  as pointing at the selection; "make it a haiku" and explicit "selected" /
  "highlighted" still transform.
- **GTK clipboard lost after a Wayland paste** (#199). A plain-text copy
  from a native GTK app was treated as rich content (it advertises
  `COMPOUND_TEXT`), so the clipboard was not restored after a paste and the
  diagnostics blamed HTML. Real rich content still blocks the restore.
- **Media pause with two instances of one player** (#205). With one mpv
  paused and another playing, the playing one kept playing and resume
  started both. Players are now tracked and controlled per instance; a
  paused instance that has gone away is not replaced by a sibling.
- **ydotool advice** (#193). When the ydotool test keystroke fails,
  **Text insertion** now points to **Set up ydotool** (a session-scoped
  `/dev/uinput` rule) instead of telling you to join the `input` group,
  which grants read access to every keyboard.

### Profiles

- **Task and Language overrides show labels** (#196). **Task** listed raw
  values and showed an empty box for "no override"; it now offers "Use
  global default", "Transcribe" and "Translate to English". **Language**
  shows "Use global default", "Auto detect" and native language names, and
  a saved code outside the list stays selectable.
- **Activation read "On On"** (#189). The switch's own label is the only
  one now.
- **Revert browser URL detection** (#194) now shows whether the revert
  worked, instead of immediately overwriting the result with the computed
  state.

### Providers and plugins

- **Codex CLI failed every request** (#198). Codex rejected TypeWhisper's
  `tools.view_image` override under `--strict-config`. It now passes
  `features.view_image=false`, requires Codex 0.147 or later, and a CLI that
  rejects TypeWhisper's settings gets its own message (update TypeWhisper
  or use an older CLI) instead of a misleading network error.
- **Claude Code CLI returned no structured result** (#191). The blanket
  tool deny also blocked the `StructuredOutput` tool that `--json-schema`
  needs. Only MCP tools are denied now; built-in tools stay removed with
  `--tools ""`.
- **OpenCode logins not recognized** (#192). OpenCode 1.19 renamed its
  provider from "OpenCode Zen" to "OpenCode", so a signed-in install showed
  "Login status cannot be checked safely". Both names and the raw
  `opencode` ID are recognized; "OpenCode Go" is not mistaken for it.
- **GitHub Copilot accounts failed to load** (#195). Anyone signed into the
  `gh` CLI saw "The signed-in accounts could not be read", because the
  runtime listed the gh login without a token and the SDK rejected the
  whole list. The runtime now runs with a private `gh` stub first on its
  `PATH`. Copilot's own logins are unaffected; a `gh` login still does not
  sign you in to Copilot.
- **AssemblyAI streaming faulted** (#190). Held-back short audio was merged
  into the next full second and sent as one 1,039 ms message, which
  AssemblyAI rejects. Messages are now split to at most 1000 ms.
- **xAI key reported invalid on a team without credits** (#207). A new
  team's valid key failed **Test** with "API key is invalid". It now says
  the key was accepted but the team needs credits or a license at
  console.x.ai; other 403s point at the key's permissions.

### File transcription

- **Subtitle cues going negative or backwards** (#203). A provider segment
  with a negative start or an end before its start produced invalid SRT and
  VTT timestamps. Cues now start at zero or later and never end before they
  start, in the watch-folder, file-transcription and HTTP API exports.

## Removed

- **Online plugin registry** (#197). Startup fetched a plugin catalog URL
  that was never published (HTTP 404) and retried on every launch. The
  registry service, its startup stages and the `PluginFirstRunCompleted`
  setting are gone; settings files that still contain it load normally.
  Bundled plugins deploy as before.

## Plugin SDK

- No SDK changes. Bundled plugins keep `minHostVersion` 0.19.0.
- Bundled plugin versions: AssemblyAI 1.2.2, Authenticated CLIs 1.1.2,
  GitHub Copilot 1.0.1, xAI 1.2.1. Every other bundled plugin is
  unchanged.

## Under the Hood

- Avalonia 12.0.1 → 12.1.4 and `Tmds.DBus.Protocol` 0.92 → 0.94.1 (#204).
  The nine D-Bus signal subscriptions (AT-SPI, learned corrections, logind)
  pass `EmitOnConnectionFailed`, so they keep recovering after a bus
  disconnect as they did on 0.92.
- The never-run plugin publishing workflow and
  `scripts/publish-plugin-release.ps1` are removed (#197).
  `plugins/catalog.json` stays for packaging, and its test now counts
  plugins from the catalog.
- Two GitHub Copilot plugin tests that raced their own background catalog
  refresh now wait for it (#207).

## Notes

- Not run end to end: native Wayland drag and drop, GTK3 Wayland clipboard
  restore and the browser URL detection revert against a live app. Media
  pause was verified against fake MPRIS players, not real mpv.
